## 1. 引言

### 1.1 编写目的

本文档定义红蓝对抗平台的技术规范，包括技术栈选择、编程规范、代码组织、配置管理和开发环境要求。本文档的目标读者为项目开发人员，确保团队在开发过程中遵循统一的技术标准。

本文档适用于红蓝对抗平台的所有代码开发，包括后端 Python 代码、前端 TypeScript 代码、数据库设计和配置文件。

## 3. 后端技术规范

### 3.1 编程语言规范

**Python 版本**：Python 3.10 及以上。

**类型注解**：所有函数必须使用类型注解，包括参数类型和返回类型。使用 `from __future__ import annotations` 启用延迟求值。示例：

```python
from __future__ import annotations
from collections.abc import Callable

def create_task(
    db: Session,
    *,
    target_agent: str,
    risk_types: list[str],
    max_rounds: int,
) -> Task:
    ...
```

**模块导入**：使用绝对导入路径，以 backend 为根包名。示例：

```python
from backend.storage.models import Task
from backend.config import get_settings
```

**文档字符串**：每个模块文件顶部使用 `"""docstring"""` 格式的三引号注释，描述模块功能。

### 3.2 异步编程规范

**协程声明**：异步函数使用 `async def` 声明。

**并发执行**：使用 `asyncio.gather` 并发执行多个协程任务。

**线程池**：CPU 密集型或阻塞操作使用 `ThreadPoolExecutor`，通过 `asyncio.get_running_loop().run_in_executor` 委托执行。

**后台任务**：WebSocket 推送使用 `asyncio.create_task` 创建后台协程，不阻塞主线程。

### 3.3 API 设计规范

**RESTful 风格**：遵循 REST 设计原则，使用标准 HTTP 方法。

**路由前缀**：所有任务相关 API 路由前缀为 `/api/tasks`。

**路径参数**：使用花括号语法 `{task_id}` 定义路径参数。

**查询参数**：所有查询参数定义在函数签名中，FastAPI 自动解析。

**请求体**：使用 Pydantic BaseModel 定义请求体模型。

**响应模型**：使用 `response_model` 参数指定响应模型，FastAPI 自动序列化。

**依赖注入**：数据库会话通过 FastAPI 的 `Depends(get_db)` 注入。

**状态码**：使用 FastAPI 的 `status_code` 参数指定响应状态码。

### 3.4 数据模型规范

**Pydantic 模型**：所有数据结构使用 Pydantic 的 BaseModel 定义，支持 `from_attributes=True` 从 ORM 对象转换。

**可选字段**：使用 `| None` 类型标注可选字段。

**默认值**：使用 `Field(default_factory=dict)` 为可变类型提供默认值。

**别名映射**：使用 `Field(alias="model_config")` 处理 Python 关键字冲突。

### 3.5 数据库规范

**ORM 模型**：使用 SQLAlchemy 的 `DeclarativeBase` 定义模型。

**主键**：所有表使用 VARCHAR(64) 字符串主键，格式为 `{表名前缀}_{uuid4().hex[:12]}`。

**外键**：使用 `ForeignKey` 定义外键关系，设置 `ondelete="CASCADE"` 级联删除。

**关系**：使用 `relationship` 定义双向关联，`back_populates` 指定反向引用。

**索引**：对 status、task_id、attack_case_id、trace_id、event_type、risk_level、risk_type 等常用查询字段建立索引。

**JSON 字段**：使用 `JSON` 类型存储列表和字典数据。

**会话管理**：使用 `sessionmaker` 创建会话工厂，`autocommit=False`，`autoflush=False`。

**连接池**：SQLite 单线程模式，使用 `check_same_thread=False` 参数。

### 3.6 事件驱动规范

**事件定义**：事件类型使用 Python 枚举（Enum）定义。FastPathEvent 和 SlowPathEvent 使用 dataclass 定义，包含 event_type、context、data 字段。

**EventContext**：所有事件必须包含 EventContext，包含 task_id、trace_id、round_id、attack_case_id 四个字段。

**事件发布**：
- Fast Path 事件使用 `publish(event)` 同步发布
- Slow Path 事件使用 `publish(event)` 异步发布
- 回合结果事件使用 `publish_until_outcome(event)` 获取 RoundOutcome 返回值

**事件隔离**：Fast Path 和 Slow Path 事件完全隔离，使用不同的总线实例和事件类型枚举。

### 3.7 配置管理规范

**Settings 类**：使用 Pydantic 的 BaseSettings 定义配置类，自动从环境变量加载。

**配置项**：所有配置项使用大写字母和下划线命名，并设置默认值。

**YAML 配置文件**：检测策略（blue_policies.yaml）和目标智能体（target_agents.yaml）使用 YAML 格式。

**LLM 超时**：单次 LLM 调用超时时间为 120 秒。

**WebSocket 推送**：每 0.5 秒推送一次任务状态快照。

### 3.8 错误处理规范

**LLM 模型调用**：解析 LLM 返回结果时，使用多层容错策略：先尝试 JSON 解析，再尝试从字典中提取常见字段，最后剥离 Markdown 代码块标记取纯文本。

**任务执行**：使用 try/except 包裹整个任务执行流程，异常时更新任务状态为 FAILED 并记录错误信息到数据库。

**变异任务**：变异执行异常时捕获并记录，不中断主流程。

**Ollama 健康检查**：启动任务前检查 Ollama 服务可用性，不可用时返回 503 错误。

**Slow Path 失败**：Slow Path 处理器异常通过 on_failure 回调记录，不影响主流程。

### 3.9 安全规范

**输入验证**：对用户输入的 redbench_datasets 进行白名单校验，不在可用数据集列表中的返回 400 错误。

**参数上限**：max_rounds 参数默认为 2，防止无限循环。

**API 密钥**：DeepSeek API 密钥通过环境变量配置，不硬编码在代码中。

**沙箱隔离**：工具执行在沙箱环境中进行，提供 Python 沙箱和 WASM 沙箱两种隔离方式。

**数据库安全**：数据库文件存储在本地文件系统，不在 web 可访问目录中。

## 4. 前端技术规范

### 4.1 编程语言规范

**TypeScript**：所有前端代码使用 TypeScript，充分利用类型系统。

**组件定义**：使用 Vue 3 的 Composition API（`<script setup lang="ts">`）定义组件。

**类型定义**：通过 `@/types` 目录统一管理类型定义。

### 4.2 状态管理规范

**Pinia Store**：使用 Pinia 的 `defineStore` 创建状态仓库，采用组合式 API 风格。

**状态更新**：使用 `applyTaskSnapshot` 方法统一处理 WebSocket 推送的状态更新。

**响应式断连**：WebSocket 连接状态通过 `isConnected` ref 追踪，断线时自动重连。

### 4.3 组件开发规范

**组件拆分**：主视图 WorkspaceView 组合 6 个子组件，每个组件职责单一。

**Propers 传递**：父子组件间通过 props 传递数据，使用 `defineProps` 声明。

**事件通信**：组件间通过 Pinia Store 共享状态，避免深层 prop 传递。

**样式隔离**：使用 `<style scoped>` 实现组件样式隔离。

### 4.4 HTTP 和 WebSocket 规范

**Axios 实例**：创建统一的 Axios 实例，配置 baseURL 和默认超时时间。

**WebSocket 连接**：通过 `new WebSocket(url)` 创建连接，监听 `onmessage`、`onerror`、`onclose` 事件。

**自动重连**：连接关闭时，1.5 秒后自动重连，使用 `reconnectTimer` 管理。

**路由感知**：重连时检查当前路由，仅当包含任务 ID 时发起重连。

### 4.5 可视化规范

**ECharts 图表**：使用 ECharts 的 `init` 方法初始化图表，通过 `setOption` 更新数据。

**图表自适应**：监听 `window.resize` 事件，调用 `resize` 方法自适应窗口大小。

**图表销毁**：组件卸载时调用 `dispose` 方法销毁图表实例。

## 7. 关键算法说明

### 7.1 并发检测算法

蓝队输入检测和输出检测采用双通道并发检测算法：

1. 创建两个协程任务：规则引擎检测和 LLM 模型检测
2. 使用 asyncio.gather 并发执行两个任务
3. 规则引擎通常先完成，若命中高风险且判定为阻断，取消 LLM 检测任务以节省开销
4. 合并两个通道的检测结果，优先采用更严格的判定

### 7.2 变异策略选择算法

红队根据失败阶段自动选择变异策略，采用以下映射规则：

- 失败在 input 阶段且非降级：优先 semantic_rewrite，备选 role_context_shift
- 失败在 tool_call 阶段且非降级：优先 lower_risk_tool_sequence，备选 multi_turn_indirection
- 失败在 tool_call 阶段且降级：优先 objective_decomposition，备选 lower_risk_tool_sequence
- 失败在 output 阶段且非降级：优先 objective_decomposition，备选 multi_turn_indirection
- 其他情况：默认 semantic_rewrite

### 7.3 版本比对算法

WebSocket 推送采用版本比对减少不必要的数据传输：

1. 计算当前快照的版本号，基于：任务状态 + 当前轮次 + 更新时间 + 攻击用例数量 + 变异任务数量 + 检测结果数量 + 审计事件数量 + 评估报告 ID + 错误信息
2. 比对当前版本号与上次推送的版本号
3. 仅在版本号不同时推送数据
4. 任务完成（COMPLETED 或 FAILED）后强制推送最后一次

### 7.4 Payload 多层容错解析

红队 LLM 生成或变异 Payload 时，对返回结果进行多层容错解析：

1. 第一层：尝试 JSON 解析（json.loads）
2. 第二层：若失败，尝试从字典中提取常见字段（如 "payload"、"mutated_prompt"、"text"、"content"）
3. 第三层：若仍失败，剥离 Markdown 代码块标记（```json ... ```），取纯文本内容
4. 最终层：若全部失败，抛出异常通知上层处理

### 7.5 评估指标计算

- 攻击成功率 = 成功攻击数 / 总攻击数
- 检测率 = 检测到的攻击数 / 总攻击数
- 阻断率 = 阻断的攻击数 / 总攻击数
- 误报率 = 被检测为异常但实际安全的比例
- 漏报率 = 未被检测到的攻击比例
- 风险覆盖率 = 已覆盖风险类型数 / 请求风险类型总数

# 红蓝对抗平台 — 系统设计文档

---

## 1. 引言

### 1.1 编写目的

本文档从技术架构角度描述红蓝对抗平台的系统设计，包括系统架构、模块分层、组件设计、数据流设计和技术选型。本文档的目标读者为开发人员和技术评审人员。

### 1.2 设计原则

- **模块化**：系统划分为 9 个独立模块，模块间通过事件总线通信，降低耦合度
- **事件驱动**：采用双总线架构，同步执行路径与异步可观测路径分离
- **状态机编排**：通过 LangGraph 状态图编排红蓝对抗的主流程
- **可扩展性**：支持 YAML 配置文件扩展检测策略、目标智能体和攻击模板

## 2. 系统架构概述

### 2.1 整体架构

系统采用前后端分离的 B/S 架构，后端为 Python FastAPI 服务，前端为 Vue 3 单页面应用。后端通过 LangGraph 状态图编排红蓝对抗流程，采用双总线事件驱动架构实现模块解耦。

```
+---------------------------+     +---------------------------+
|        前端 (Vue 3)        |     |      后端 (FastAPI)        |
|                           |     |                           |
|  - WorkspaceView          |<--->|  - REST API (7 endpoints) |
|  - LeftSidebar            |HTTP |  - WebSocket (1 endpoint) |
|  - TaskHeader             |     |                           |
|  - ActionGraph            |<--->|  - Orchestrator           |
|  - DataViewer             | WS  |  - RedTeam                |
|  - SecurityInsights       |     |  - BlueTeam               |
|  - AuditTimeline          |     |  - Targets                |
|                           |     |  - Evaluation             |
+---------------------------+     |  - EventBus               |
                                  |  - Storage                |
                                  |  - LLM                     |
                                  |  - Observability           |
                                  +---------------------------+
                                            |
                                  +---------+---------+
                                  |         |         |
                              Ollama    DeepSeek   SQLite
                              (本地)    (外部API)  (本地文件)
```

### 2.2 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| 后端框架 | FastAPI | 高性能异步框架，原生支持 WebSocket，自动生成 OpenAPI 文档 |
| 流程编排 | LangGraph | 基于状态图的 DAG 编排，支持节点间状态传递和条件路由 |
| 数据库 | SQLite + SQLAlchemy | 轻量级嵌入式数据库，无需独立部署；ORM 提供类型安全 |
| 前端框架 | Vue 3 + TypeScript | 响应式数据绑定，TypeScript 类型安全 |
| 状态管理 | Pinia | Vue 3 官方推荐，支持组合式 API |
| 可视化 | ECharts | 丰富的图表类型，支持动态更新 |
| UI 组件 | Element Plus | 成熟的 Vue 3 组件库 |
| 红队模型 | dolphin-mistral:latest | 开源模型，对指令遵循度较高，适合攻击生成 |
| 蓝队模型 | gemma2:2b | 轻量级模型，推理速度快，适合实时检测 |
| 目标模型 | qwen3:1.7b | 轻量级模型，模拟真实 AI Agent 行为 |
| 评估模型 | deepseek-v4-flash | 外部 API，推理能力强，适合生成评估报告 |

## 4. 双总线事件驱动架构

### 4.1 设计目标

将系统的执行流程和可观测事件分离，确保：
- 执行流程（攻击、检测、评估）在同步的 Fast Path 中完成，保证数据一致性
- 可观测事件（审计、日志、追踪、指标）在异步的 Slow Path 中完成，不阻塞主流程

### 4.2 Fast Path 同步总线

Fast Path Bus 负责管理红蓝攻防的执行路径，采用同步的发布-订阅模式。

**核心特性**：
- 同步执行：publish 方法同步调用所有订阅者
- 事件历史：所有事件记录在 history 列表中
- 回合结果：publish_until_outcome 方法支持获取 RoundOutcome 类型的返回值
- 13 种事件类型，覆盖攻防执行全路径

**实现**：FastPathBus 类维护一个 handlers 字典（按事件类型分组）和一个 history 列表。publish 方法遍历对应事件类型的所有处理器，同步执行并收集结果。

### 4.3 Slow Path 异步总线

Slow Path Bus 负责承载可观测事件，采用异步非阻塞的执行模式。

**核心特性**：
- 异步执行：publish 方法通过 asyncio.create_task 将处理器放入后台任务
- 失败处理：支持 on_failure 回调，记录处理器异常
- 批量等待：drain 方法等待所有后台任务完成
- 同步兼容：无运行事件循环时，自动降级为同步执行
- 8 种事件类型，覆盖审计、追踪、指标等可观测领域

**实现**：SlowPathBus 类维护 handlers 字典、background_tasks 集合和 failure_handler。publish 方法获取当前事件循环，为每个处理器创建后台任务，任务完成后自动从集合中移除。

### 4.4 默认处理器注册

register_default_handlers 函数自动为所有 SlowPathEventType 枚举值注册 InMemoryTelemetrySink 处理器。InMemoryTelemetrySink 类按事件类型分桶存储事件数据，包含 8 个列表字段分别对应 8 种事件类型。

### 4.5 事件上下文

所有事件（Fast Path 和 Slow Path）都包含 EventContext，包含四个字段：
- task_id：任务 ID，关联到具体任务
- trace_id：追踪 ID，关联到单次攻击执行
- round_id：回合 ID（可选）
- attack_case_id：攻击用例 ID（可选）

通过 EventContext 可以实现全链路追踪，从任务创建到最终评估的所有事件均可追溯。

## 5. LangGraph 状态图编排

### 5.1 状态图结构

系统通过 LangGraph 的 StateGraph 构建 DAG 执行流程，定义三个节点：

```
[plan_attack_chain] --> [dispatch_defense_pipeline] --> [evaluate_stream] --> [END]
```

### 5.2 节点 1：plan_attack_chain（攻击链规划）

**职责**：初始化红队指挥官，生成攻击用例列表。

**输入**：AttackTaskState（任务配置参数）
**输出**：AttackTaskState（包含 attack_cases 列表）

**执行逻辑**：
1. 创建 RedTeamCommander 实例
2. 根据 redbench_datasets 确定风险类型
3. 设置 attack_count（确保至少为 1）
4. 调用 commander.plan_attack_chain 生成攻击用例
5. 将攻击用例写入 state

### 5.3 节点 2：dispatch_defense_pipeline（防御分发）

**职责**：逐个执行攻击用例，协调红蓝对抗，管理变异进化。

**输入**：AttackTaskState（包含 attack_cases）
**输出**：AttackTaskState（包含 round_results、更新后的 attack_cases）

**执行逻辑**：
1. 初始化 FastPathBus、SlowPathBus、ThreadPoolExecutor
2. 维护 pending_cases 队列和 mutation_futures 字典
3. 循环处理：
   - 优先从 pending_cases 取出攻击用例执行
   - 执行完毕后判断是否需要进化，若需要则提交异步变异任务
   - 当 pending_cases 为空时，等待变异任务完成
   - 变异完成后将新用例追加到 pending_cases 队尾
4. 所有用例处理完毕后，更新 state

**变异管理**：
- 使用 ThreadPoolExecutor（max_workers=1）异步执行变异
- 变异任务提交后记录 REDTEAM_MUTATION_QUEUED 审计事件
- 变异完成后发布 REDTEAM_EVOLVED 审计事件
- 每个回合完成后通过 on_round_complete 回调触发数据库持久化

### 5.4 节点 3：evaluate_stream（评估流）

**职责**：生成评估报告，追加审计事件。

**输入**：AttackTaskState（包含 round_results）
**输出**：AttackTaskState（包含 evaluation_result）

**执行逻辑**：
1. 调用 build_evaluation_report 生成评估报告
2. 追加 EVALUATION_METRIC 审计事件（包含评估指标）
3. 追加 REPORT_EVENT 审计事件（包含链路追踪数据）
4. 将审计事件导出到 state

### 5.5 单次攻击执行流程

_execute_attack_case 函数实现单次攻击的 6 个阶段：

**阶段 1：攻击请求**
- 构建攻击请求（AttackExecutor.build_request）
- 发布 ATTACK_REQUEST 事件（Fast Path）
- 记录 ATTACK_REQUESTED 审计事件（Slow Path）

**阶段 2：输入检测**
- 发布 INPUT_RECEIVED 事件（Fast Path）
- 调用 BlueTeamCommander.inspect_input 进行输入检测
- 发布 DEFENSE_FEEDBACK 事件（Slow Path）
- 若被阻断（action == "block"），发布 ROUND_OUTCOME 并返回

**阶段 3：目标执行**
- 发布 INPUT_ALLOWED 事件（Fast Path）
- 调用 TargetManager.plan_action 获取目标智能体决策
- 发布 AGENT_ACTION 事件（Fast Path）
- 若无工具调用，直接进入输出检测

**阶段 4：工具审计**
- 调用 BlueTeamCommander.audit_tool 进行工具审计
- 发布 TOOL_ALLOWED / TOOL_BLOCKED / TOOL_DEGRADED 事件（Fast Path）
- 若被阻断，发布 ROUND_OUTCOME 并返回
- 若被降级，使用降级后的工具调用

**阶段 5：沙箱执行**
- 调用 TargetManager.execute_tool 在沙箱中执行工具
- 发布 TARGET_EXECUTION_RESULT 事件（Fast Path）
- 若工具审计结果为降级，在此阶段返回回合结果

**阶段 6：输出检测**
- 调用 BlueTeamCommander.inspect_output 进行输出检测
- 发布 OUTPUT_ALLOWED / OUTPUT_BLOCKED 事件（Fast Path）
- 返回回合结果

## 9. 部署架构

### 9.1 部署方式

系统采用单机部署架构：

```
[浏览器] --HTTP/WS--> [FastAPI 服务 (uvicorn)] --SQL--> [SQLite 文件]
                           |
                           +--HTTP--> [Ollama 服务 (localhost:11434)]
                           |
                           +--HTTPS--> [DeepSeek API (api.deepseek.com)]
```

### 9.2 启动流程

1. 启动 Ollama 服务，确保所需模型已拉取
2. 启动 FastAPI 服务（uvicorn backend.main:app）
3. FastAPI 启动时自动调用 init_db 创建数据库表
4. 前端通过 Vite 开发服务器或构建后的静态文件提供服务

### 9.3 配置管理

系统配置通过 Settings 数据类管理，支持环境变量覆盖：

- DATABASE_URL：数据库连接字符串（默认 sqlite:///./red_blue_platform.db）
- OLLAMA_BASE_URL：Ollama 服务地址（默认 http://localhost:11434）
- RED_MODEL：红队模型（默认 dolphin-mistral:latest）
- TARGET_MODEL：目标模型（默认 qwen3:1.7b）
- BLUE_MODEL：蓝队模型（默认 gemma2:2b）
- EVAL_MODEL：评估模型（默认 deepseek-v4-flash）
- DEFAULT_MAX_ROUNDS：默认最大轮次（默认 2）
- LLM_TIMEOUT：LLM 调用超时（默认 120 秒）
- EXTERNAL_EVAL_API_BASE_URL：外部评估 API 地址
- EXTERNAL_EVAL_API_KEY：外部评估 API 密钥

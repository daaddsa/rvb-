# 红蓝对抗平台 — 数据库说明书

---

## 1. 引言

### 1.1 编写目的

本文档详细描述红蓝对抗平台的数据库设计，包括数据库选型、表结构定义、字段说明、索引设计、实体关系图和数据操作接口。本文档的目标读者为开发人员和数据库维护人员。

### 1.2 数据库选型

| 项目 | 说明 |
|------|------|
| 数据库类型 | SQLite 3.x |
| 选型理由 | 轻量级嵌入式数据库，无需独立部署，零配置，适合学生实训项目；单文件存储便于备份和迁移 |
| ORM 框架 | SQLAlchemy 2.x |
| 连接方式 | 本地文件连接，check_same_thread=False |
| 默认路径 | ./red_blue_platform.db |

---

## 2. 数据库连接配置

### 2.1 连接字符串

默认连接字符串：

```
sqlite:///./red_blue_platform.db
```

可通过环境变量 `DATABASE_URL` 覆盖。

### 2.2 连接管理

- 使用 SQLAlchemy 的 `create_engine` 创建引擎，配置 `check_same_thread=False` 以支持多线程访问
- 使用 `sessionmaker` 创建会话工厂，配置 `autocommit=False`、`autoflush=False`
- 每次请求通过 `get_db` 依赖注入获取独立会话，请求结束后自动关闭
- 应用启动时通过 `init_db` 函数自动创建所有表

### 2.3 连接池

SQLite 单线程模式，不使用连接池。每个请求获取独立会话，操作完成后立即关闭。

## 3. 表结构设计

系统共设计 5 张核心数据表，以下分别详细说明。

### 3.1 tasks 表 — 任务表

**表说明**：存储红蓝对抗任务的基本信息，是整个系统的核心表。

| 字段名 | 类型 | 长度 | 主键 | 外键 | 索引 | 非空 | 默认值 | 说明 |
|--------|------|------|------|------|------|------|--------|------|
| id | VARCHAR | 64 | 是 | - | - | 是 | - | 任务 ID，格式：task_{uuid4_hex[12]} |
| status | VARCHAR | 32 | - | - | 是 | 是 | - | 任务状态：PENDING / RUNNING / COMPLETED / FAILED |
| target_agent | VARCHAR | 128 | - | - | 是 | 是 | - | 目标智能体类型：financial_agent / customer_agent |
| risk_types | JSON | - | - | - | - | 否 | - | 风险类型列表，如 ["ASI01", "ASI02"] |
| attack_skills | JSON | - | - | - | - | 否 | - | 攻击技能 ID 列表 |
| attack_count | INTEGER | - | - | - | - | 是 | - | 攻击用例总数 |
| current_round | INTEGER | - | - | - | - | 是 | - | 当前执行轮次 |
| max_rounds | INTEGER | - | - | - | - | 是 | - | 最大对抗轮次 |
| use_llm | BOOLEAN | - | - | - | - | 是 | - | 是否使用 LLM 生成攻击 |
| model_config | JSON | - | - | - | - | 否 | - | 模型配置对象 |
| red_model | VARCHAR | 128 | - | - | - | 否 | - | 红队模型名称 |
| target_model | VARCHAR | 128 | - | - | - | 否 | - | 目标模型名称 |
| blue_model | VARCHAR | 128 | - | - | - | 否 | - | 蓝队模型名称 |
| eval_model | VARCHAR | 128 | - | - | - | 否 | - | 评估模型名称 |
| matrix_version | VARCHAR | 64 | - | - | - | 是 | - | 攻击矩阵版本，如 ASI_2026 |
| created_at | DATETIME | - | - | - | - | 是 | - | 创建时间，自动生成 |
| updated_at | DATETIME | - | - | - | - | 是 | - | 更新时间，自动更新 |
| error | TEXT | - | - | - | - | 否 | - | 错误信息，任务失败时记录 |

**索引说明**：
- status 索引：用于快速查询不同状态的任务列表
- target_agent 索引：用于按目标智能体类型筛选任务

**状态流转**：

```
PENDING → RUNNING → COMPLETED
                  → FAILED
```

**JSON 字段示例**：

risk_types 字段：
```json
["ASI01", "ASI02", "ASI03"]
```

attack_skills 字段：
```json
["direct_jailbreak", "role_override"]
```

model_config 字段：
```json
{
  "target_model": "qwen3:1.7b"
}
```

### 3.2 attack_cases 表 — 攻击用例表

**表说明**：存储红队生成的攻击用例，包括原始攻击和变异进化后的攻击。

| 字段名 | 类型 | 长度 | 主键 | 外键 | 索引 | 非空 | 默认值 | 说明 |
|--------|------|------|------|------|------|------|--------|------|
| id | VARCHAR | 64 | 是 | - | - | 是 | - | 用例 ID，格式：case_{uuid4_hex[12]} |
| task_id | VARCHAR | 64 | - | tasks.id | - | 是 | - | 所属任务 ID，级联删除 |
| risk_chain_id | VARCHAR | 64 | - | - | 是 | 否 | - | 风险链 ID，关联同一攻击链的多轮变异 |
| round_no | INTEGER | - | - | - | 是 | 是 | - | 轮次编号，从 1 开始 |
| skill_id | VARCHAR | 128 | - | - | 是 | 否 | - | 攻击技能 ID |
| risk_type | VARCHAR | 64 | - | - | 是 | 否 | - | 风险类型，如 ASI01 |
| target_agent | VARCHAR | 128 | - | - | 是 | 是 | - | 目标智能体类型 |
| prompt | TEXT | - | - | - | - | 是 | - | 攻击提示词文本内容 |
| expected_violation | TEXT | - | - | - | - | 否 | - | 预期违规类型描述 |
| severity | VARCHAR | 32 | - | - | - | 否 | - | 严重程度：low / medium / high / critical |
| model_name | VARCHAR | 128 | - | - | - | 否 | - | 生成该用例的模型名称 |
| parent_case_id | VARCHAR | 64 | - | attack_cases.id | - | 否 | - | 父用例 ID，标识变异来源 |
| mutation_strategy | VARCHAR | 128 | - | - | - | 否 | - | 变异策略名称 |
| created_at | DATETIME | - | - | - | - | 是 | - | 创建时间 |

**索引说明**：
- task_id（外键自动索引）：用于按任务查询攻击用例
- risk_chain_id 索引：用于追踪同一风险链的所有变异用例
- round_no 索引：用于按轮次筛选
- skill_id 索引：用于按攻击技能分类
- risk_type 索引：用于按风险类型分类
- target_agent 索引：用于按目标智能体分类

**级联关系**：
- task_id 外键：删除任务时，级联删除所有关联攻击用例
- parent_case_id 外键：自引用，标识变异来源

### 3.3 detection_results 表 — 检测结果表

**表说明**：存储蓝队三道防线的检测结果，每次检测记录一条。

| 字段名 | 类型 | 长度 | 主键 | 外键 | 索引 | 非空 | 默认值 | 说明 |
|--------|------|------|------|------|------|------|--------|------|
| id | VARCHAR | 64 | 是 | - | - | 是 | - | 检测结果 ID，格式：detection_{uuid4_hex[12]} |
| task_id | VARCHAR | 64 | - | tasks.id | - | 是 | - | 所属任务 ID，级联删除 |
| attack_case_id | VARCHAR | 64 | - | attack_cases.id | - | 否 | - | 关联攻击用例 ID，级联删除 |
| stage | VARCHAR | 32 | - | - | 是 | 是 | - | 检测阶段：input / tool_call / output / round |
| detector | VARCHAR | 128 | - | - | 是 | 是 | - | 检测器名称，如 rule_engine / llm_model |
| model_name | VARCHAR | 128 | - | - | - | 否 | - | 使用的模型名称 |
| detected | BOOLEAN | - | - | - | - | 是 | - | 是否检测到异常 |
| blocked | BOOLEAN | - | - | - | - | 是 | - | 是否被阻断 |
| action | VARCHAR | 32 | - | - | - | 是 | - | 动作：allow / block / degrade |
| risk_level | VARCHAR | 32 | - | - | 是 | 否 | - | 风险等级：low / medium / high / critical |
| risk_type | VARCHAR | 64 | - | - | 是 | 否 | - | 风险类型：ASI01 至 ASI07 |
| reason | TEXT | - | - | - | - | 否 | - | 检测原因描述 |
| confidence | FLOAT | - | - | - | - | 否 | - | 置信度，范围 0.0 到 1.0 |
| raw_output | JSON | - | - | - | - | 否 | - | 原始检测输出，保存完整检测结果 |
| created_at | DATETIME | - | - | - | - | 是 | - | 创建时间 |

**索引说明**：
- task_id（外键自动索引）：用于按任务查询检测结果
- attack_case_id（外键自动索引）：用于按攻击用例查询
- stage 索引：用于按检测阶段筛选
- detector 索引：用于按检测器分类
- risk_level 索引：用于按风险等级统计
- risk_type 索引：用于按风险类型统计

**级联关系**：
- task_id 外键：删除任务时，级联删除所有关联检测结果
- attack_case_id 外键：删除攻击用例时，级联删除关联检测结果

**stage 字段说明**：

| 值 | 说明 | 对应防线 |
|----|------|---------|
| input | 输入检测阶段 | 第一道防线 |
| tool_call | 工具审计阶段 | 第二道防线 |
| output | 输出检测阶段 | 第三道防线 |
| round | 回合汇总 | 回合级检测结果 |

**action 字段说明**：

| 值 | 说明 | 后续流程 |
|----|------|---------|
| allow | 放行 | 继续执行 |
| block | 阻断 | 停止执行，返回回合结果 |
| degrade | 降级 | 继续执行但使用降级后的参数 |

| event_topic | VARCHAR | 64 | - | - | 是 | 否 | - | 事件主题：FAST_PATH / SLOW_PATH |
| agent | VARCHAR | 128 | - | - | 是 | 否 | - | 执行代理：redteam / blueteam / financial_agent / customer_agent / evaluation |
| tool_name | VARCHAR | 128 | - | - | 是 | 否 | - | 工具名称，如 query_balance / transfer_money |
| payload | JSON | - | - | - | - | 否 | - | 事件载荷，存储事件相关数据 |
| allowed | BOOLEAN | - | - | - | - | 否 | - | 是否被允许（仅适用于检测类事件） |
| risk_level | VARCHAR | 32 | - | - | 是 | 否 | - | 风险等级 |
| risk_type | VARCHAR | 64 | - | - | 是 | 否 | - | 风险类型 |

| summary | TEXT | - | - | - | - | 否 | - | 评估摘要 |

## 4. 实体关系图

```
┌──────────────────────────────────────────────────────────────┐
│                          tasks                                │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ id (PK)  │ status │ target_agent │ max_rounds │ ... │    │
│  └──────────────────────────────────────────────────────┘    │
└──────────────────────────┬───────────────────────────────────┘
                           │ 1
                           │
           ┌───────────────┼───────────────┬───────────────┐
           │ N             │ N             │ N             │ 1
           ▼               ▼               ▼               ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐ ┌──────────────────────┐
│  attack_cases    │ │detection_results │ │  audit_events    │ │  evaluation_reports  │
│  ┌────────────┐  │ │  ┌────────────┐  │ │  ┌────────────┐  │ │  ┌────────────────┐  │
│  │ id (PK)    │  │ │  │ id (PK)    │  │ │  │ id (PK)    │  │ │  │ id (PK)        │  │
│  │ task_id FK │  │ │  │ task_id FK │  │ │  │ task_id FK │  │ │  │ task_id FK UQ  │  │
│  │ parent_id  │──┼─┼─>│ case_id FK │  │ │  │ case_id FK │  │ │  │ total_attacks  │  │
│  │   FK (self)│  │ │  │ stage      │  │ │  │ trace_id   │  │ │  │ detection_rate │  │
│  │ prompt     │  │ │  │ action     │  │ │  │ event_type │  │ │  │ ...            │  │
│  │ ...        │  │ │  │ ...        │  │ │  │ ...        │  │ │  └────────────────┘  │
│  └────────────┘  │ │  └────────────┘  │ │  └────────────┘  │ └──────────────────────┘
│  N               │ │  N               │ │  N               │
│  │               │ │  ▲               │ │  ▲               │
│  └───────────────┘ │  │               │ │  │               │
```

**关系说明**：

| 关系 | 类型 | 说明 |
|------|------|------|
| tasks → attack_cases | 1:N | 一个任务包含多个攻击用例 |
| tasks → detection_results | 1:N | 一个任务产生多个检测结果 |
| tasks → audit_events | 1:N | 一个任务产生多个审计事件 |
| tasks → evaluation_reports | 1:1 | 一个任务对应一份评估报告 |
| attack_cases → detection_results | 1:N | 一个攻击用例产生多个检测结果（多道防线） |
| attack_cases → audit_events | 1:N | 一个攻击用例产生多个审计事件 |
| attack_cases → attack_cases | 自引用 1:N | 一个攻击用例可变异出多个子用例 |

## 5. 数据操作说明

### 5.1 数据创建

- **任务创建**：用户通过 API 创建任务时，在 tasks 表中插入一条记录，状态为 PENDING
- **攻击用例创建**：红队生成攻击链时，在 attack_cases 表中批量插入攻击用例
- **检测结果创建**：蓝队每次检测完成后，在 detection_results 表中插入检测结果
- **审计事件创建**：通过 SlowPathBus 异步写入 audit_events 表
- **评估报告创建**：评估阶段完成后，在 evaluation_reports 表中插入报告

### 5.2 数据更新

- **任务状态更新**：启动任务后更新为 RUNNING，完成后更新为 COMPLETED，失败时更新为 FAILED
- **任务轮次更新**：每完成一个回合，更新 current_round 字段
- **任务时间更新**：每次状态变更时，自动更新 updated_at 字段

### 5.3 数据查询

- **任务列表**：按 created_at 降序查询所有任务
- **任务详情**：按 task_id 查询任务，并关联查询 attack_cases、detection_results、evaluation_reports
- **评估报告**：按 task_id 查询 evaluation_reports 表
- **审计事件**：按 task_id 查询 audit_events 表，按 created_at 升序排列

### 5.4 数据删除

- 使用外键级联删除（ondelete="CASCADE"），删除任务时自动删除所有关联数据
- 删除攻击用例时，级联删除其 detection_results 和 audit_events 记录

### 5.5 CRUD 操作接口

| 函数 | 操作 | 说明 |
|------|------|------|
| create_task | INSERT | 创建任务记录 |
| get_task | SELECT + JOIN | 查询任务详情，包含关联数据 |
| list_tasks | SELECT | 查询任务列表，按创建时间倒序 |
| update_task_status | UPDATE | 更新任务状态 |
| get_task_report | SELECT | 查询评估报告 |
| list_task_events | SELECT | 查询审计事件列表 |
| persist_round | INSERT + UPDATE | 持久化回合数据到多张表 |

## 6. 性能优化建议

### 6.1 索引优化

已为高频查询字段建立索引，包括：
- status、target_agent（tasks 表）
- risk_chain_id、round_no、skill_id、risk_type、target_agent（attack_cases 表）
- stage、detector、risk_level、risk_type（detection_results 表）
- trace_id、event_type、event_topic、agent、tool_name、risk_level、risk_type（audit_events 表）

### 6.2 查询优化

- 任务详情查询使用 JOIN 一次性加载关联数据，避免 N+1 查询
- 审计事件按时间升序排列，分页加载
- 评估报告通过 task_id 唯一约束确保单次查询

### 6.3 数据清理

- 当前 SQLite 数据库文件可能随时间增长，建议定期清理历史任务数据
- 可通过删除旧任务记录实现级联清理所有关联数据

## 8. 附录

### 8.1 主键 ID 生成规则

所有表的主键使用统一格式：`{前缀}_{uuid4().hex[:12]}`，其中前缀根据表名确定：

| 表 | 前缀 | 示例 |
|----|------|------|
| tasks | task_ | task_a1b2c3d4e5f6 |
| attack_cases | case_ | case_a1b2c3d4e5f6 |
| detection_results | detection_ | detection_a1b2c3d4e5f6 |
| audit_events | audit_ | audit_a1b2c3d4e5f6 |
| evaluation_reports | report_ | report_a1b2c3d4e5f6 |

### 8.2 时间字段说明

- 所有时间字段使用 Python datetime 类型
- 数据库中存储为 SQLite DATETIME 格式（ISO 8601）
- created_at 在记录创建时自动设置为当前时间
- updated_at 在记录每次更新时自动更新为当前时间
- 时间均为 UTC 时间

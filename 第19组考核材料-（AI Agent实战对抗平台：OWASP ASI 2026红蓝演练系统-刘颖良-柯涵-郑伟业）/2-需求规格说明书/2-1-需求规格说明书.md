## 1. 引言
### 1.1 编写目的
本文档旨在详细描述红蓝对抗平台的功能需求和非功能需求，为系统设计、开发和测试提供依据。本文档的目标读者包括项目开发人员、测试人员、项目管理人员和指导老师。

本需求规格说明书作为整个软件项目实训的核心交付文档，承担多重作用：
1. **对开发组内部**：统一3名开发人员对业务、接口、边界条件的理解，避免红队、蓝队、前端模块出现需求理解偏差，作为日常开发参照依据；
2. **对测试人员**：提供完整的测试依据，所有功能需求均可转化为测试用例，指导功能测试、集成测试、边界测试；
3. **对项目管理/指导教师**：用于确认项目范围，界定哪些功能属于本期实现，哪些属于未来扩展，评估项目工作量，跟踪开发完成度；
4. **作为后续文档输入**：本说明书是系统设计文档、接口说明书、用户手册、验收测试计划的前置输入，后续所有文档均需要回溯本需求文档。

本文档将明确系统的输入输出、业务规则、异常场景、性能指标、外部依赖，同时划定**项目的范围边界**，明确本版本不实现的功能，避免项目开发过程中出现范围蔓延。

### 1.2 项目背景
随着大模型技术快速落地，AI Agent智能体被广泛应用在金融客服、自动化办公、业务处理系统中。AI Agent具备调用外部工具、访问业务数据、执行操作的能力，在带来便利的同时引入大量安全风险：攻击者通过精心构造提示词实现提示词注入、角色冒充、越权调用工具、窃取业务敏感数据等攻击行为。

传统大模型安全评估大多采用静态数据集单轮测试，存在明显短板：
1. 仅使用固定样本，无法模拟攻击者不断改写payload进行绕过的对抗过程；
2. 缺少闭环对抗，攻击被拦截后不会自动改写攻击提示词进行二次尝试；
3. 缺少统一量化评估指标，测试结果大多为定性描述，难以横向对比不同防御策略的防护效果；
4. 缺少可视化流程展示，攻防执行过程黑盒化，审计、排查问题困难。

针对上述行业痛点，本项目开发面向AI Agent安全评估的自动化红蓝对抗演练平台。平台通过红队模拟攻击、蓝队部署防御、目标智能体执行和评估报告生成四位一体的闭环流程，为AI Agent的安全评估提供完整的工具支持。平台模拟真实攻防场景：红队发起攻击，蓝队多层防线拦截，攻击被拦截后自动变异改写攻击提示词实现持续对抗，最终输出量化评估报告，帮助开发人员发现AI Agent安全缺陷，辅助优化防御策略。

本项目属于软件实训项目，基于开源数据集与开源大模型完成原型实现，重点验证“攻击‑检测‑变异‑再攻击”闭环对抗流程，可用于教学演示、AI安全实验，后续可迭代扩展用于企业内部安全测评。

> **项目范围边界（本期不实现）**
> 1. 不支持接入第三方外部真实业务AI Agent，仅使用平台内置模拟金融、客服智能体；
> 2. 不实现分布式集群部署，仅支持单机部署运行；
> 3. 不实现多用户账号权限管理，本期仅支持单用户使用；
> 4. 不支持自定义编写全新变异策略，仅支持配置启用/禁用系统内置5种变异策略。

### 1.3 术语定义
| 术语 | 定义 |
|------|------|
| 红队 | 负责生成攻击提示词和进行 Payload 变异的模块 |
| 蓝队 | 负责输入检测、工具审计和输出检测的防御模块 |
| 目标智能体 | 被评估的 AI Agent，模拟金融或客服业务场景 |
| Payload | 红队生成的攻击提示词文本 |
| 变异 | 红队根据蓝队检测结果对攻击 Payload 进行改写的过程 |
| RedBench | AI 安全基准测试数据集，包含多种风险类型的攻击样本 |
| Fast Path | 同步事件总线，处理攻防执行流程中的阻塞事件 |
| Slow Path | 异步事件总线，处理审计日志、模型追踪等可观测事件 |
| 风险类型 | 攻击行为的分类，如 ASI01（直接越权）、ASI02（角色冒充）等 |
| 闭环对抗 | “攻击发起→蓝队检测→执行结果反馈→Payload变异→再次发起攻击”完整循环流程 |
| 双通道并发检测 | 蓝队同时运行规则引擎与LLM语义检测，并行计算检测结果再合并判定 |
| 沙箱执行环境 | 隔离运行工具调用逻辑，防止工具调用产生真实业务副作用的模拟运行环境 |
| 变异链 | 原始攻击用例经过多次变异，父用例‑子用例形成的攻击演化链条 |

## 2. 系统概述
### 2.1 系统总体描述
红蓝对抗平台是一个基于 B/S 架构的 Web 应用系统，采用前后端分离架构。后端使用 Python FastAPI 框架提供 RESTful API 和 WebSocket 服务，前端使用 Vue 3 + TypeScript框架构建单页面应用。系统通过 LangGraph编排红蓝对抗的执行流程，支持基于 RedBench 数据集的自动攻击用例生成和基于 EvoSafety 策略的对抗性 Payload 自动进化。

后端整体采用事件驱动双总线架构，区分Fast Path同步事件总线、Slow Path异步事件总线；业务流程由LangGraph状态图进行编排，把复杂攻防流程拆解为有限状态节点，便于调试、扩展、日志追踪。
数据持久化使用SQLite本地数据库，所有任务、攻击用例、检测结果、审计事件全部落盘存储。大模型推理全部依托Ollama本地服务，评估能力可切换至DeepSeek外部API。
前端为浏览器访问SPA单页应用，无需安装客户端；后端为单机服务，用户在浏览器访问本地地址即可完成全部对抗评估操作。

### 2.2 系统功能概述
系统主要功能包括：
1. **任务管理**：创建、启动、查询和删除红蓝对抗任务。
2. **红队攻击生成**：从 RedBench 数据集加载攻击提示词，或通过 LLM 生成攻击用例。
3. **蓝队防御检测**：对红队攻击进行输入检测、工具审计和输出检测三道防线。
4. **目标系统模拟**：模拟金融智能体和客服智能体的行为，包括 LLM 决策和工具调用。
5. **自动进化**：红队根据蓝队检测结果自动变异 Payload，实现持续对抗。
6. **评估报告**：自动计算核心指标，生成评估报告和修复建议。
7. **实时可视化**：通过 WebSocket 实时推送任务进度，前端可视化展示对抗流程。

**业务完整流程简述：**
用户在前端创建对抗任务，选择数据集、目标智能体、最大对抗轮次；用户点击启动任务后后端开始执行。红队生成攻击用例，提交攻击；攻击首先经过蓝队输入检测；放行后交由目标智能体做决策；智能体如需调用工具，则进入蓝队工具审计；审计放行后沙箱执行工具；工具执行完毕，蓝队输出检测校验返回内容；回合结束，统计回合结果。如果攻击被蓝队拦截，满足条件就触发红队变异，生成改写后的新攻击用例进入对抗队列循环执行，直到达到最大轮次。全部回合结束后自动计算指标生成评估报告，前端实时展示每一步的状态、审计事件、图表指标。

### 2.3 用户角色
| 角色 | 权限 |
|------|------|
| 系统用户 | 创建任务、启动任务、查看任务列表、查看任务详情、查看评估报告、查看审计事件 |

> **用户特征补充描述**
本系统面向实训场景，系统用户为测评人员/实验人员。用户具备基础AI安全相关知识，能够理解ASI风险类型、攻击、防御、变异等概念；用户操作环境为普通PC浏览器。本期版本不区分管理员与普通用户，所有操作权限全部开放。未来版本扩展可增加管理员角色，实现多用户隔离、任务权限管控、策略文件网页编辑等能力。

**用户操作场景示例：**
> 场景1：测评人员想要测试金融智能体的防御效果。打开网页，选择financial_agent，勾选多个RedBench数据集，设置最大轮次，创建并启动任务，等待执行完成，查看评估报告，分析哪些攻击类型防御失效。
> 场景2：观察攻击变异绕过防御。查看态势流程图，观察某一条攻击被蓝队block之后，系统自动生成变异后的payload，继续尝试绕过蓝队三道防线，观察变异链演化过程。

## 3. 功能性需求
### 3.1 任务管理功能
#### 3.1.1 创建任务
**功能描述**：用户通过前端界面创建红蓝对抗任务，配置任务参数。
**输入参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| target_agent | string | 是 | 目标智能体类型，可选值：financial_agent、customer_agent |
| redbench_datasets | string[] | 是 | 选择的 RedBench 数据集列表，至少选择一个 |
| attack_skills | string[] | 否 | 攻击技能列表，可为空 |
| max_rounds | integer | 是 | 最大对抗轮次，最小值为 1，默认值为 2 |
| matrix_version | string | 否 | 攻击矩阵版本，默认值为 ASI_2026 |
| llm_models.target_model | string | 否 | 目标模型名称，不指定则使用默认值 |

**输出结果**：返回任务 ID、初始状态和矩阵版本。
**业务规则**：
- RedBench 数据集至少选择一个，否则返回 400 错误。
- 选择的数据集必须在系统可用数据集列表中，否则返回 400 错误并列出无效数据集。
- 攻击数量自动根据所选数据集的样本数量确定。
- 风险类型自动根据所选数据集的类型映射确定。

**异常场景补充（新增）**
1. max_rounds传入0、负数，接口返回400参数校验错误，提示最大对抗轮次必须大于等于1；
2. target_agent传入不在枚举内的字符串，返回400，提示目标智能体仅支持financial_agent、customer_agent；
3. llm_models.target_model传入模型名称，但Ollama本地不存在该模型，任务创建成功，但启动任务时执行健康检查失败返回503；
4. 请求体JSON格式非法，后端返回400 JSON解析错误。

**任务初始状态**：任务创建完成后状态固定为`PENDING`（待启动），不会自动运行，必须调用启动接口才会开始对抗流程。

#### 3.1.2 启动任务
**功能描述**：用户启动已创建的任务，系统开始执行红蓝对抗流程。
**前置条件**：任务状态为 PENDING。
**处理流程**：
1. 校验任务状态是否为 PENDING，否则返回 400 错误。
2. 执行 Ollama 服务健康检查，若不可用返回 503 错误。
3. 将任务状态更新为 RUNNING。
4. 启动后台线程执行任务编排流程。

**输出结果**：返回任务 ID 和更新后的状态。

**异常与边界场景补充**
1. 对RUNNING、COMPLETED、FAILED状态的任务重复调用启动接口：返回400，提示任务状态不允许启动；
2. Ollama服务连通但指定模型未下载：返回503，并提示缺少对应模型名称；
3. 后台线程启动失败：任务状态置为FAILED，保存错误堆栈信息存入数据库，可在任务详情查看失败原因。

> 注意：任务一旦进入RUNNING状态，**本期版本不提供暂停、终止接口**，任务只能运行到结束或者出现异常失败；未来迭代版本可增加任务停止功能。

#### 3.1.3 任务列表
**功能描述**：查询所有已创建的任务列表。
**输出结果**：返回所有任务的列表，包含任务 ID、状态、目标智能体、创建时间等基本信息。

**补充业务规则**
1. 查询结果按创建时间倒序排列，最新创建任务排在列表最上方；
2. 如果系统没有任何任务，返回空数组，不返回报错；
3. 列表接口不返回全部明细数据，只返回摘要，详细数据通过任务详情接口获取，减少接口数据量。

#### 3.1.4 任务详情
**功能描述**：查询指定任务的详细信息。
**输入参数**：任务 ID。
**输出结果**：返回任务基本信息、攻击用例列表、变异任务列表、检测结果列表和评估报告。

**补充业务规则**
1. 任务ID不存在时返回404；
2. 攻击用例需要携带变异父子关系字段，前端可据此渲染变异链；
3. 如果任务还在RUNNING执行中，评估报告字段返回null。

#### 3.1.5 评估报告
**功能描述**：查询指定任务的评估报告。
**输入参数**：任务 ID。
**输出结果**：返回评估报告，包含攻击成功率、检测率、阻断率、误报率、漏报率、风险覆盖率、RedBench 基线对比、风险细分和修复建议。若报告尚未生成，返回提示信息。

#### 3.1.6 审计事件
**功能描述**：查询指定任务的审计事件列表。
**输入参数**：任务 ID。
**输出结果**：返回该任务的所有审计事件，每个事件包含事件类型、事件主题、执行代理、工具名称、风险等级、风险类型和消息内容。

**补充业务规则**：事件按照事件发生时间升序返回，方便前端渲染时间线；支持后续扩展分页参数，本期实现返回全部事件。

#### 3.1.7 RedBench 数据集列表
**功能描述**：查询系统可用的 RedBench 数据集列表。
**输出结果**：返回所有可用数据集名称的列表。

**补充说明**：系统启动时扫描数据集目录下的parquet文件生成可用列表；如果目录无数据集文件，返回空数组。

### 3.2 红队攻击生成功能
#### 3.2.1 攻击链规划
**功能描述**：红队根据任务配置生成攻击用例列表。
**处理流程**：
1. 根据用户选择的 RedBench 数据集，从 Parquet 文件中加载攻击提示词记录。
2. 优先使用 RedBench 数据集中的真实攻击样本作为攻击用例。
3. 当数据集样本不足时，调用红队 LLM 模型补充生成攻击提示词。
4. 为每个攻击用例分配唯一 ID、风险链 ID、技能 ID 等属性。
5. 记录攻击用例的元数据，包括数据来源（redbench 或 llm）、数据集名称、行索引、类别等。

**攻击用例属性**：每个攻击用例包含以下字段：用例 ID、风险链 ID、轮次编号、技能 ID、风险类型、目标智能体、攻击提示词、预期违规类型、严重程度、父用例 ID（变异来源）、变异策略、元数据。
**风险类型**：系统支持 7 类风险类型（ASI01 至 ASI07），包括直接越权、角色冒充、工具滥用链、审批绕过、数据窃取、多轮间接攻击、低风险工具链攻击等。

**补充边界说明**
1. 数据集加载异常（parquet文件损坏）：记录错误审计事件，任务状态置FAILED；
2. 数据集样本数量为0：自动触发LLM生成攻击用例进行补充；
3. 每一条原始样本作为**初始攻击用例**；变异产生的新用例属于子用例，拥有父用例ID。

#### 3.2.2 攻击提示词生成
**功能描述**：当 RedBench 数据集样本不足时，通过红队 LLM 模型生成攻击提示词。
**处理流程**：
1. 使用红队系统提示词，将模型定位为“AI Agent 安全评估平台中的红队测试者”。
2. 向模型传入任务配置参数（目标智能体、风险类型、攻击技能、攻击数量等）。
3. 要求模型返回纯 JSON 字符串数组，每个元素为一个攻击提示词。
4. 解析返回结果，校验数量是否满足要求。
5. 若数量不足，抛出异常通知上层处理。

> 补充说明：此处模型调用并非用于恶意攻击，而是安全测评场景，系统提示词明确告知模型目的是AI安全测试评估，规避模型安全对齐拒绝输出的问题。如果大模型仍然拒绝输出攻击样本，则记录审计事件，任务不会直接崩溃，尽可能复用已加载的RedBench样本继续执行。

#### 3.2.3 攻击请求构建
**功能描述**：将攻击用例转换为可执行的攻击请求。
**输出**：包含攻击提示词、追踪 ID 等信息的攻击请求对象。

> 补充：追踪ID贯穿Fast Path事件总线，从攻击发起直到回合结束，所有事件携带同一个追踪ID，用于链路排查。

### 3.3 蓝队防御检测功能
蓝队防御检测分为三道防线，依次为：输入检测、工具审计和输出检测。
> **防线逻辑说明（新增）**
三道防线属于顺序执行关系：输入检测拦截，则不会走到工具审计、输出检测；输入放行才进入目标智能体决策；智能体调用工具才会执行工具审计；工具执行完毕，无论是否调用工具，都要执行输出检测。三道防线各司其职：输入检测拦截恶意用户输入；工具审计拦截危险工具调用行为；输出检测拦截结果泄露。

#### 3.3.1 输入检测
**功能描述**：在攻击请求到达目标智能体之前，对攻击提示词进行安全检测。
**检测方式**：采用规则引擎和 LLM 模型双通道并发检测。
- **规则引擎通道**：基于预定义的关键词规则进行匹配，检查提示词中是否包含越权指令、敏感操作请求等高风险内容。
- **LLM 模型通道**：通过蓝队 LLM 模型对提示词进行语义理解，判断是否存在恶意意图。

**并发策略**：
- 两个通道通过 Python 协程并发执行。
- 规则引擎通常先完成，若命中高风险且判定为阻断，立即取消模型检测任务以节省开销。
- 合并两个通道的检测结果，优先采用更严格的判定（阻断优先于降级，降级优先于允许）。

**检测结果**：包含以下字段：动作（allow、block、degrade）、风险等级（low、medium、high、critical）、风险类型、检测原因、置信度、匹配的规则列表。
**路径分支**：
- 若检测结果为 block，直接返回回合结果，不再执行后续阶段。
- 若检测结果为 allow，继续执行目标执行阶段。

> 补充说明：degrade降级动作在输入检测场景下本期版本仅做记录，不修改输入提示词；降级主要应用于工具审计环节，对工具参数脱敏。

#### 3.3.2 工具审计
**功能描述**：当目标智能体决定调用工具时，对工具调用进行安全审计。
**审计内容**：
- **角色权限校验**：检查调用者是否具备执行该工具的权限。
- **敏感字段检查**：检查工具调用的参数中是否包含敏感字段，如目标账户、金额、导出字段等。
- **LLM 辅助审计**：通过蓝队 LLM 模型对工具调用进行语义层面的安全评估。

**审计结果**：包含以下字段：动作（allow、block、degrade）、风险等级、风险类型、审计原因、匹配的规则列表、降级后的工具调用。
**路径分支**：
- 若审计结果为 block，直接返回回合结果。
- 若审计结果为 degrade，使用降级后的工具参数继续执行。
- 若审计结果为 allow，使用原始工具调用继续执行。

> 降级示例场景：工具参数携带身份证号，降级动作会将身份证脱敏替换为`***`，继续执行沙箱调用。

#### 3.3.3 输出检测
**功能描述**：在目标智能体执行完成后，对输出内容进行安全检测。
**检测方式**：与输入检测相同，采用规则引擎和 LLM 模型双通道并发检测。
**检测内容**：检查目标智能体的响应和执行结果中是否包含敏感信息泄露、越权操作结果等高风险内容。
**检测结果**：与输入检测格式相同。

### 3.4 目标系统模拟功能
#### 3.4.1 目标智能体管理
**功能描述**：管理可用的目标智能体类型及其配置。
**内置智能体**：
| 智能体 ID | 名称 | 描述 | 可用工具 |
|-----------|------|------|---------|
| financial_agent | 金融智能体 | 处理余额查询、转账和风控审核 | query_balance、transfer_money、risk_review、query_customer_summary |
| customer_agent | 客服智能体 | 处理订单查询、用户信息查询和工单修改 | query_order、query_user_info、update_ticket、query_customer_summary |

**扩展方式**：支持通过 YAML 配置文件（target_agents.yaml）扩展新的目标智能体类型。

> 补充说明：新增智能体只需要编写yaml配置，定义描述、系统提示词、可用工具集合，不需要修改后端核心代码，体现可扩展性。但是新增工具仍需要后端注册工具函数。

#### 3.4.2 目标智能体决策
**功能描述**：目标智能体根据攻击提示词进行 LLM 决策，判断是否执行工具调用。
**处理流程**：
1. 获取目标智能体配置（ID、名称、描述、可用工具列表）。
2. 将攻击提示词和目标智能体信息组装为 Prompt。
3. 调用目标 LLM 模型，要求返回 JSON 格式的响应。
4. 解析返回结果，提取响应文本和工具调用计划。
5. 若 LLM 返回格式异常，返回纯文本响应（无工具调用）。

**输出**：包含智能体 ID、响应文本和工具调用计划（可选）的决策结果。

> 补充异常场景：大模型输出JSON格式错乱，无法解析工具调用，则视为智能体不调用任何工具，直接输出文本回答，流程继续走到输出检测，任务不会崩溃。

#### 3.4.3 沙箱工具执行
**功能描述**：在沙箱环境中安全执行工具调用。
**沙箱环境**：使用 Python 沙箱执行器，通过工具注册表管理可用工具。
**工具注册表**：系统内置 9 个工具函数：
| 工具名称 | 功能 | 返回示例 |
|---------|------|---------|
| query_balance | 查询账户余额 | 余额 12888 元 |
| transfer_money | 执行转账 | 转账状态 submitted |
| risk_review | 风控审核 | 风险等级 medium，未通过 |
| query_order | 查询订单 | 订单状态 paid |
| query_user_info | 查询用户信息 | 姓名、手机号、身份证号 |
| update_ticket | 修改工单 | 工单状态更新 |
| export_customer_data | 导出客户数据 | 敏感字段样本数据 |
| query_customer_summary | 查询客户摘要 | 客户数量、风险分布 |
| admin_update_user | 修改用户角色 | 角色变更待审核 |

> 补充说明：全部工具均为模拟工具，不会产生真实转账、数据修改，仅返回预设样例数据；沙箱隔离目的是防止恶意代码执行，本期优先实现Python层面逻辑隔离。

### 3.5 自动进化功能
#### 3.5.1 进化判定
**功能描述**：根据回合结果判定是否需要执行红队进化。
**判定条件**：
- 攻击成功（action 为 allow），不需要进化。
- 下一轮次超过最大轮次限制，不需要进化。
- 当前用例的变异次数已达到最大轮次，不需要进化。
- 其余情况，需要进化。

> 补充：单条攻击用例最多变异次数等于任务配置max_rounds，防止无限变异循环。

#### 3.5.2 变异策略选择
**功能描述**：根据失败阶段自动选择最优的变异策略。
**策略映射**：
| 失败阶段 | 是否降级 | 推荐策略 |
|---------|---------|---------|
| input | 否 | semantic_rewrite、role_context_shift |
| tool_call | 否 | lower_risk_tool_sequence、multi_turn_indirection |
| tool_call | 是 | objective_decomposition、lower_risk_tool_sequence |
| output | 否 | objective_decomposition、multi_turn_indirection |
| 其他 | 否 | semantic_rewrite |

**变异策略说明**：
| 策略名称 | 说明 |
|---------|------|
| semantic_rewrite | 语义重写，保持攻击意图但改变表达方式 |
| role_context_shift | 角色上下文转换，将攻击融入业务场景 |
| lower_risk_tool_sequence | 低风险工具序列，先调用低风险工具建立信任 |
| multi_turn_indirection | 多轮迂回，通过多轮对话逐步引导 |
| objective_decomposition | 目标分解，将攻击目标拆分为多个子步骤 |

> 补充业务说明：系统内置5种变异策略，本期版本不支持用户自定义新策略，后续迭代可以通过配置文件扩展策略集合。

#### 3.5.3 异步变异执行
**功能描述**：通过线程池异步执行变异任务，不阻塞主流程。
**处理流程**：
1. 构建变异任务，包含父用例、回合结果、下一轮次和变异策略。
2. 通过线程池（最大工作线程数为 1）提交变异任务。
3. 发布红队变异排队审计事件。
4. 主流程继续处理待执行队列中的下一个用例。
5. 变异完成后，将新用例追加到待执行队列尾部。

> 设计目的：变异依赖LLM调用，耗时较长，如果同步执行会阻塞整个攻防主循环。使用线程池异步，主流程可以并行处理其他攻击用例，提高整体执行吞吐。线程池最大1个工作线程，避免大量并发LLM请求压垮Ollama本地服务。

#### 3.5.4 Payload 变异重写
**功能描述**：通过 LLM 对原始 Payload 进行语义重写，生成新的攻击提示词。
**处理流程**：
1. 组装变异重写提示词，包含原始 Payload、目标智能体、风险类型、变异策略、失败阶段、失败原因和红队提示。
2. 调用红队 LLM 模型进行重写。
3. 对返回结果进行多层容错解析：先尝试 JSON 解析，再尝试从字典中提取常见字段，最后剥离 Markdown 代码块标记取纯文本。
4. 若解析失败，抛出异常。
5. 构建新的攻击用例，包含父用例 ID、变异策略、更新的元数据等信息。

> 补充异常说明：变异解析失败，记录审计事件，该次变异直接放弃，不会生成子用例，不会中断整个任务的运行。

### 3.6 评估报告功能
#### 3.6.1 指标计算
**功能描述**：基于回合结果计算核心评估指标。
**核心指标**：
| 指标 | 计算方式 |
|------|---------|
| 总攻击数 | 所有攻击用例数量 |
| 成功攻击数 | action 为 allow 的回合数 |
| 检测攻击数 | action 为 block 或 degrade 的回合数 |
| 阻断攻击数 | action 为 block 的回合数 |
| 攻击成功率 | 成功攻击数 / 总攻击数 |
| 检测率 | 检测攻击数 / 总攻击数 |
| 阻断率 | 阻断攻击数 / 总攻击数 |
| 误报率 | 检测为异常但实际安全的比例 |
| 漏报率 | 未检测到的攻击比例 |
| 风险覆盖率 | 已覆盖的风险类型与总请求风险类型的比例 |

> 补充：分母为0时，指标设置为null，前端做特殊渲染，避免除零报错。

#### 3.6.2 RedBench 基准对比
**功能描述**：将平台检测结果与 RedBench 基线数据进行对比。
**对比维度**：按风险类型逐一对比检测率，计算 delta 差值，标识低于基线的风险类型。

#### 3.6.3 评分
**功能描述**：基于严重程度权重和动作风险分数进行加权评分。
**输出**：防御得分（百分比）、残余风险分数、各风险类型的加权评分。

> 权重示例：critical风险权重最高，low风险权重最低；block动作获得满分，degrade部分得分，allow不得分。

#### 3.6.4 AI 评估报告
**功能描述**：通过 DeepSeek 评估模型生成综合评估报告。
**报告内容**：从红方视角、目标系统视角、蓝方模型视角三个维度分析攻击效果和防御能力，提供修复建议。
**兜底策略**：当 DeepSeek API 不可用时，自动使用规则引擎生成摘要和建议。

### 3.7 实时可视化功能
#### 3.7.1 WebSocket 实时推送
**功能描述**：通过 WebSocket 协议向客户端实时推送任务执行进度。
**端点**：`/api/tasks/{task_id}/stream`
**推送频率**：每 0.5 秒一次。
**推送内容**：任务基本信息、攻击用例列表、变异任务列表、检测结果、审计事件、评估报告。
**版本比对**：根据任务状态、当前轮次、更新时间、攻击用例数量、变异任务数量、检测结果数量、审计事件数量、评估报告 ID 等生成快照版本号，仅在版本变化时才推送。
**连接管理**：任务完成（COMPLETED 或 FAILED）后自动关闭连接；客户端断开连接时自动清理。

> 版本比对机制目的：避免WebSocket高频重复推送完全一样的数据，降低浏览器渲染压力和后端网络开销。

#### 3.7.2 前端可视化组件
**功能描述**：前端通过 6 个核心组件展示对抗流程和结果。
**组件列表**：
| 组件 | 功能 |
|------|------|
| LeftSidebar | 任务创建弹窗：数据集多选、目标智能体选择、轮次上限配置 |
| TaskHeader | 任务状态徽章、时间显示、开始执行按钮 |
| ActionGraph | 六阶段流程可视化：攻击请求→输入检测→目标决策→工具审计→沙箱执行→输出检测，含状态着色和动画效果 |
| DataViewer | 三方输出对比展示：红队提示词、目标响应、蓝队检测结果，变异任务卡片轮播 |
| SecurityInsights | ECharts 指标图表、AI 总结报告渲染、最终指标卡片 |
| AuditTimeline | Fast Path 和 Slow Path 事件时间线，含颜色编码和工具标签 |

> 补充界面交互细节：ActionGraph流程图每个节点使用颜色区分状态：灰色等待、蓝色执行中、绿色放行、红色阻断；AuditTimeline时间线支持鼠标hover查看事件详情。

## 4. 非功能性需求
### 4.1 性能需求
| 指标 | 要求 |
|------|------|
| API 响应时间 | 创建任务、查询任务等操作应在 1 秒内响应 |
| WebSocket 推送延迟 | 状态变化后 0.5 秒内推送到前端 |
| 并发检测 | 规则引擎和 LLM 模型在 2 个协程内并发执行 |
| 变异执行 | 通过线程池异步执行，不阻塞主流程 |
| LLM 调用超时 | 单次调用超时时间为 120 秒 |

**补充性能约束（新增）**
1. 单机部署场景，不支持同时运行2个及以上RUNNING状态任务，多任务同时启动会出现模型调用资源竞争，属于本期版本限制；
2. SQLite数据库，任务记录规模建议不超过100个任务，大量任务会降低列表接口查询速度；
3. WebSocket单任务连接最大在线时长设置30分钟，超过自动断开，防止闲置连接占用资源。

### 4.2 可用性需求
| 指标 | 要求 |
|------|------|
| Ollama 健康检查 | 启动任务前自动检查 Ollama 服务可用性 |
| 断线重连 | WebSocket 断线后 1.5 秒间隔自动重连 |
| 错误处理 | 任务执行异常时状态更新为 FAILED，错误信息持久化 |
| 模型兜底 | LLM 生成不足时自动回退到 RedBench 数据集 |

**补充可用性说明**
1. 系统发生异常崩溃，重启服务后不会自动恢复正在运行的任务，正在RUNNING的任务状态不会自动继续执行，需要用户重新创建任务；
2. 所有错误信息存入数据库，用户可以查看失败任务详情定位问题；
3. YAML策略配置文件格式错误：系统启动阶段检测，输出提示日志，不直接崩溃，使用内置默认策略运行。

### 4.3 安全性需求
- 蓝队检测策略支持 YAML 配置文件，可在不修改代码的情况下调整防御规则。
- 工具执行在沙箱环境中进行，提供 Python 沙箱和 WASM 沙箱两种隔离方式。
- 所有审计事件包含任务 ID 和追踪 ID，确保全链路可追溯。

> 补充安全说明：本系统为测评实训平台，**不面向公网部署**，仅本地内网访问，本期不实现身份认证、接口鉴权；如果后续公网部署，需要增加登录鉴权、输入防注入等安全加固。

### 4.4 可扩展性需求
- 支持通过 YAML 配置文件扩展目标智能体类型和工具。
- 支持通过攻击模板库扩展攻击技能。
- 支持通过 RedBench 数据集扩展攻击样本。
- 模块之间通过事件总线通信，新增模块只需订阅相关事件。

> 扩展示例：新增一个日志导出模块，只需要订阅Slow Path审计事件，不需要修改红队蓝队业务代码，实现模块解耦。

## 5. 数据需求
### 5.1 数据实体
系统包含以下核心数据实体：
1. **任务（Task）**：红蓝对抗任务的基本信息，包括状态、目标智能体、风险类型、攻击技能、模型配置等。
2. **攻击用例（AttackCase）**：每次攻击的详细信息，包括提示词、风险类型、变异策略、父子关系等。
3. **检测结果（DetectionResult）**：每次检测的结果，包括阶段、动作、风险等级、置信度等。
4. **审计事件（AuditEvent）**：Fast Path 和 Slow Path 的所有事件记录。
5. **评估报告（EvaluationReport）**：任务的评估指标和修复建议。

### 5.2 数据关系
- 一个任务包含多个攻击用例、多个检测结果、多个审计事件和一个评估报告。
- 一个攻击用例包含多个检测结果和多个审计事件。
- 攻击用例之间通过 parent_case_id 形成父子关系（变异链）。
- 删除任务时，级联删除所有关联的攻击用例、检测结果、审计事件和评估报告。

> 补充：数据库索引设计，task_id在各个子表建立索引，提升任务详情查询性能。

## 6. 外部接口需求
### 6.1 用户接口
- **前端界面**：基于 Vue 3 的单页面应用，提供任务管理、对抗流程可视化、评估报告展示等功能。
- **交互方式**：用户通过浏览器访问前端界面，进行操作。

> 补充UI约束：页面适配1920*1080分辨率；暂不做移动端适配，只面向PC浏览器操作。

### 6.2 硬件接口
无特殊硬件接口需求。系统运行在标准 x86 架构计算机上，需要支持 Ollama 本地模型运行的 GPU 或 CPU 资源。

## 9. 验收准则（全新增加章节）
> 每个功能需求都具备可验证的验收标准，分为功能验收、非功能验收。

### 9.1 功能验收通用规则
1. 所有REST接口调用返回格式符合接口文档，错误场景返回对应HTTP状态码；
2. 创建任务→启动任务→执行对抗→生成报告完整流程可以跑完，无程序崩溃；
3. 红队可以加载RedBench数据集，数据集不足可调用LLM生成攻击；
4. 蓝队输入检测、工具审计、输出检测三道防线可以正常执行，支持block/degrade/allow动作；
5. 攻击被拦截满足条件时自动触发Payload变异；
6. WebSocket能够实时推送任务进度，前端流程图、审计时间线正常渲染；
7. 任务结束自动计算6项以上核心安全指标，输出评估报告；
8. YAML策略修改可以改变蓝队检测行为，不需要修改源代码。

### 9.2 非功能验收准则
1. 普通查询API响应时间小于1秒；
2. WebSocket断线后前端可以自动重连；
3. LLM调用超时120秒后任务不会卡死，记录错误状态；
4. 任务异常时状态置FAILED，错误信息持久保存，可查询。

## 10. 风险分析（全新增加章节）
| 风险编号 | 风险描述 | 可能性 | 影响程度 | 缓解措施 |
|---|---|---|---|---|
| R1 | 开源模型安全对齐，拒绝生成攻击Payload，红队无攻击用例 | 高 | 高 | 使用RedBench数据集兜底；调整系统提示词，明确安全测评场景定位 |
| R2 | LLM输出JSON格式不稳定，Payload变异解析失败 | 中 | 中 | 多层容错解析逻辑，解析失败放弃本次变异，不中断整个任务 |
| R3 | Ollama本地模型资源占用过高，推理缓慢，任务执行时间很长 | 中 | 中 | 建议降低轮次；线程池限制并发模型调用数量 |
| R4 | WebSocket消息量大，前端页面卡顿 | 低 | 中 | 版本比对，仅数据变化推送，避免重复推送 |
| R5 | YAML策略配置写错，蓝队检测失效 | 低 | 中 | 系统启动时校验配置文件，加载内置默认策略兜底 |

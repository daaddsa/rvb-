# 红蓝对抗平台 — 接口设计说明书

---

## 1. 引言

### 1.1 编写目的

本文档详细描述红蓝对抗平台的所有接口规范，包括 REST API 接口、WebSocket 接口和内部模块之间的调用接口。本文档作为前后端开发人员、测试人员的接口契约，确保各模块之间的数据格式和通信协议一致。

### 1.2 范围

本文档涵盖以下接口：

- 面向客户端的 REST API 接口（7 个端点）
- 面向客户端的 WebSocket 实时推送接口（1 个端点）
- 内部模块接口（编排层、红队、蓝队、目标系统、评估、事件总线、持久化、LLM 调用）

### 1.3 接口命名规范

- REST API 路径前缀：`/api/tasks`
- WebSocket 路径前缀：`/api/tasks/{task_id}/stream`
- 请求方法：GET 用于查询，POST 用于创建和启动操作
- 响应格式：所有响应均为 JSON 格式
- 状态码：200 成功，201 创建成功，400 请求参数错误，404 资源不存在，503 服务不可用

## 2. REST API 接口

### 2.1 获取 RedBench 数据集列表

**接口描述**：查询系统可用的 RedBench 数据集列表，供前端创建任务时选择。

| 属性 | 值 |
|------|-----|
| 请求方法 | GET |
| 请求路径 | /api/tasks/redbench/datasets |
| 请求参数 | 无 |
| 响应模型 | RedBenchDatasetsResponse |

**响应示例**：

```json
{
  "datasets": [
    "redbench_asi01_direct_jailbreak",
    "redbench_asi02_role_override",
    "redbench_asi03_tool_misuse_chain",
    ...
  ]
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| datasets | string[] | 可用数据集名称列表 |

### 2.2 创建任务

**接口描述**：创建一个新的红蓝对抗任务。

| 属性 | 值 |
|------|-----|
| 请求方法 | POST |
| 请求路径 | /api/tasks |
| 请求模型 | TaskCreateRequest |
| 响应模型 | TaskCreateResponse |
| 成功状态码 | 201 |

**请求参数**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| target_agent | string | 是 | - | 目标智能体类型，可选值：financial_agent、customer_agent |
| redbench_datasets | string[] | 是 | - | 选择的 RedBench 数据集列表，至少选择一个 |
| attack_skills | string[] | 否 | [] | 攻击技能 ID 列表 |
| max_rounds | integer | 是 | 2 | 最大对抗轮次，最小值为 1 |
| matrix_version | string | 是 | ASI_2026 | 攻击矩阵版本 |
| model_config.target_model | string | 否 | 系统默认值 | 目标模型名称 |

**请求示例**：

```json
{
  "target_agent": "financial_agent",
  "redbench_datasets": ["redbench_asi01_direct_jailbreak"],
  "attack_skills": [],
  "max_rounds": 2,
  "matrix_version": "ASI_2026",
  "model_config": {
    "target_model": "qwen3:1.7b"
  }
}
```

**校验规则**：
- redbench_datasets 不能为空，否则返回 400 错误
- redbench_datasets 中的每个数据集必须在系统可用数据集中，否则返回 400 错误并列出无效数据集

**响应示例**：

```json
{
  "task_id": "task_a1b2c3d4e5f6",
  "status": "PENDING",
  "matrix_version": "ASI_2026"
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| task_id | string | 任务 ID，格式为 task_ 加 12 位十六进制字符 |
| status | string | 任务状态，初始为 PENDING |
| matrix_version | string | 攻击矩阵版本 |

### 2.3 启动任务

**接口描述**：启动一个已创建的任务，开始执行红蓝对抗流程。

| 属性 | 值 |
|------|-----|
| 请求方法 | POST |
| 请求路径 | /api/tasks/{task_id}/start |
| 路径参数 | task_id: string（任务 ID） |
| 响应模型 | TaskStartResponse |

**前置条件**：任务状态必须为 PENDING，否则返回 400 错误。Ollama 服务必须可用，否则返回 503 错误。

**处理流程**：
1. 校验任务存在且状态为 PENDING
2. 执行 Ollama 健康检查
3. 将任务状态更新为 RUNNING
4. 启动后台线程执行任务编排

**响应示例**：

```json
{
  "task_id": "task_a1b2c3d4e5f6",
  "status": "RUNNING"
}
```

## 3. WebSocket 实时推送接口

### 3.1 任务进度实时推送

**接口描述**：建立 WebSocket 连接，实时接收任务执行进度。

| 属性 | 值 |
|------|-----|
| 协议 | WebSocket |
| 路径 | /api/tasks/{task_id}/stream |
| 路径参数 | task_id: string（任务 ID） |
| 推送频率 | 每 0.5 秒 |
| 推送条件 | 任务状态变化时推送，无变化则跳过 |

**消息格式**：

```json
{
  "type": "task.progress",
  "data": {
    "task": { /* TaskSchema */ },
    "attack_cases": [ /* AttackCaseSchema[] */ ],
    "mutation_tasks": [ /* MutationTaskSchema[] */ ],
    "detection_results": [ /* DetectionResultSchema[] */ ],
    "report": { /* EvaluationReportSchema | null */ },
    "events": [ /* AuditEventSchema[] */ ]
  }
}
```

**消息类型**：

| type | 说明 |
|------|------|
| task.progress | 任务进度快照 |
| task.not_found | 任务不存在 |

**连接生命周期**：
- 客户端连接后，服务端立即开始推送
- 任务状态变为 COMPLETED 或 FAILED 后，发送最后一次快照，然后自动关闭连接
- 客户端断开连接时，服务端自动清理

**版本比对机制**：服务端根据以下字段生成快照版本号，仅在版本变化时推送：
- 任务状态
- 当前轮次
- 更新时间
- 攻击用例数量
- 变异任务数量
- 检测结果数量
- 审计事件数量
- 评估报告 ID
- 错误信息

## 4. 内部模块接口

### 4.1 编排层接口

编排层负责协调红蓝对抗的整体执行流程，通过 LangGraph 状态图进行编排。

**核心函数**：

| 函数 | 输入 | 输出 | 说明 |
|------|------|------|------|
| run_task | db: Session, task: Task | AttackTaskState | 任务执行主入口，初始化状态、构建图、执行编排、异常处理 |
| build_task_graph | db, task, persisted_audit_ids | CompiledStateGraph | 构建 LangGraph 状态图，包含三个节点 |
| init_task_state | task: Task | AttackTaskState | 初始化任务状态字典 |
| plan_attack_chain | state: AttackTaskState | AttackTaskState | 攻击链规划节点 |
| dispatch_defense_pipeline | state, on_round_complete | AttackTaskState | 防御分发节点 |
| evaluate_stream | state: AttackTaskState | AttackTaskState | 评估流节点 |

**AttackTaskState 数据结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| task_id | string | 任务 ID |
| target_agent | string | 目标智能体 |
| risk_types | string[] | 风险类型列表 |
| attack_skills | string[] | 攻击技能列表 |
| attack_count | integer | 攻击数量 |
| max_rounds | integer | 最大轮次 |
| matrix_version | string | 矩阵版本 |
| model_config | object | 模型配置 |
| red_model | string | 红队模型 |
| target_model | string | 目标模型 |
| blue_model | string | 蓝队模型 |
| eval_model | string | 评估模型 |
| redbench_datasets | string[] | RedBench 数据集列表 |
| attack_cases | AttackCaseState[] | 攻击用例列表 |
| mutation_tasks | MutationTaskState[] | 变异任务列表 |

## 5. 事件类型定义

### 5.1 Fast Path 事件类型

| 枚举值 | 说明 | 触发阶段 |
|--------|------|---------|
| ATTACK_REQUEST | 攻击请求发起 | 攻击执行阶段 |
| INPUT_RECEIVED | 输入已被接收 | 输入检测阶段 |
| INPUT_ALLOWED | 输入检测通过 | 输入检测阶段 |
| AGENT_ACTION | 目标智能体执行动作 | 目标执行阶段 |
| TOOL_ALLOWED | 工具调用被允许 | 工具审计阶段 |
| TOOL_BLOCKED | 工具调用被阻断 | 工具审计阶段 |
| TOOL_DEGRADED | 工具调用被降级 | 工具审计阶段 |
| TARGET_EXECUTION_RESULT | 目标执行结果 | 沙箱执行阶段 |
| OUTPUT_ALLOWED | 输出检测通过 | 输出检测阶段 |
| OUTPUT_BLOCKED | 输出被阻断 | 输出检测阶段 |
| ROUND_OUTCOME | 回合结果 | 回合结束 |
| NEXT_ROUND_REQUEST | 下一轮请求 | 回合结束 |

### 5.2 Slow Path 事件类型

| 枚举值 | 说明 | 触发时机 |
|--------|------|---------|
| DEFENSE_FEEDBACK | 防御反馈 | 每次检测后 |
| EVALUATION_METRIC | 评估指标 | 评估完成后 |
| AUDIT_LOG | 审计日志 | 审计事件发生时 |
| MODEL_TRACE | 模型调用追踪 | LLM 调用时 |
| TOOL_TRACE | 工具调用追踪 | 工具执行时 |
| REPORT_EVENT | 报告事件 | 报告生成时 |
| WEBSOCKET_EVENT | WebSocket 事件 | 推送时 |
| TASK_LIFECYCLE | 任务生命周期 | 状态变更时 |

## 6. 错误码定义

| HTTP 状态码 | 说明 | 触发条件 |
|------------|------|---------|
| 200 | 成功 | 查询操作成功 |
| 201 | 创建成功 | 任务创建成功 |
| 400 | 请求参数错误 | redbench_datasets 为空、数据集无效、任务状态不允许操作 |
| 404 | 资源不存在 | 任务 ID 不存在 |
| 503 | 服务不可用 | Ollama 服务不可用 |

错误响应格式：

```json
{
  "detail": "错误描述信息"
}
```

或当数据集无效时：

```json
{
  "detail": {
    "invalid_datasets": ["invalid_dataset_name"]
  }
}
```

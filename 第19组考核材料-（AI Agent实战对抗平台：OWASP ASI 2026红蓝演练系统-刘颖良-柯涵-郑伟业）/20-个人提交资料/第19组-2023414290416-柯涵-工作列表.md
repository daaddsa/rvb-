核心职责：攻击生成、工作流编排、LLM 调用统一管理

### 功能 A1：红队攻击模块（redteam/）
| 功能点             | 文件                                         | 说明                                           |
| ------------------ | -------------------------------------------- | ---------------------------------------------- |
| 攻击模板数据模型   | redteam/attack_state.py                      | `AttackTemplate`、`RuntimeMutation` 等数据结构 |
| 攻击模板加载器     | redteam/attack_generator.py                  | 从 YAML 加载攻击模板，内置默认模板             |
| 攻击链规划         | redteam/commander.py `plan_attack_chain()`   | 根据风险类型生成初始攻击案例                   |
| EvoSafety 攻击突变 | redteam/commander.py `mutate_attack_async()` | 根据 RoundOutcome 反馈驱动攻击进化             |
| 突变策略选择       | redteam/commander.py `_select_strategy()`    | 根据失败阶段自动选择变异策略                   |

### 功能 A2：编排引擎（orchestrator/）
| 功能点           | 文件                                             | 说明                                    |
| ---------------- | ------------------------------------------------ | --------------------------------------- |
| 运行时状态定义   | orchestrator/state.py                            | `AttackState` TypedDict，工作流状态流转 |
| 攻击规划节点     | orchestrator/nodes.py `plan_attack_node()`       | 调用红队生成攻击案例                    |
| 防御管道调度节点 | orchestrator/nodes.py `defense_pipeline_node()`  | 调用蓝队防御管道 + 目标执行             |
| 结果评估节点     | orchestrator/nodes.py `evaluate_node()`          | 生成 RoundOutcome，评估本轮结果         |
| 轮次决策节点     | orchestrator/nodes.py `decide_next_round_node()` | 判断继续攻击或生成报告                  |
| 报告生成节点     | orchestrator/nodes.py `generate_report_node()`   | 调用评估模块生成最终报告                |
| 工作流构建       | orchestrator/main_graph.py `build_main_graph()`  | LangGraph 节点连接、条件分支定义        |
| 任务执行入口     | orchestrator/main_graph.py `run_task_graph()`    | 任务启动入口，状态持久化                |

### 功能 A3：LLM 统一客户端（llm/）
| 功能点         | 文件                              | 说明                                |
| -------------- | --------------------------------- | ----------------------------------- |
| 红队模型调用   | llm/client.py `red_chat()`        | 调用红队专用模型（dolphin‑mistral） |
| 目标模型调用   | llm/client.py `target_chat()`     | 调用目标智能体模型（qwen3）         |
| 蓝队模型调用   | llm/client.py `blue_chat()`       | 调用蓝队专用模型（gemma2）          |
| 评估模型调用   | llm/client.py `eval_chat()`       | 调用评估专用模型                    |
| 多后端支持     | llm/client.py `LLMClient`         | Ollama 本地 + DeepSeek 外部 API     |
| 系统提示词模板 | llm/prompts.py                    | 红/蓝/目标/评估角色专用 prompt      |
| LLM JSON 解析  | llm/prompts.py `parse_llm_json()` | 清洗并解析 LLM JSON 输出            |

### 功能 A4：事件总线（eventbus/）
| 功能点               | 文件                                 | 说明                            |
| -------------------- | ------------------------------------ | ------------------------------- |
| 事件类型定义         | eventbus/events.py                   | FastPath/SlowPath 事件枚举      |
| 事件上下文           | eventbus/events.py `EventContext`    | task_id/trace_id/round_id 关联  |
| RoundOutcome 结构    | eventbus/events.py `RoundOutcome`    | 每轮对抗结果，用于红队演化      |
| DefenseFeedback 结构 | eventbus/events.py `DefenseFeedback` | 蓝队完整反馈，进入 SlowPath     |
| SlowPath 异步总线    | eventbus/slow_path.py `SlowPathBus`  | 发布/订阅模式，非阻塞处理器调度 |



## ⚠️ 模块间依赖关系

### 协作接口约定
1. **模块 B → 模块 A**：实现 `run_defense_pipeline()` 接口，A 直接调用
2. **模块 B → 模块 C**：实现蓝队策略配置文件 `blue_policies.yaml`，C 负责提供配置加载函数
3. **模块 A → 模块 C**：实现 `run_task_graph()` 入口，C 的 API 路由调用
4. **共享数据结构**：`events.py`（RoundOutcome / DefenseFeedback）、`storage/models.py`（ORM 模型）

# 红蓝对抗平台 — 维护手册

---

## 1. 系统概述

本文档面向红蓝对抗平台的系统维护人员，介绍系统的日常维护操作、常见问题排查和故障恢复方法。

### 1.1 系统组成

| 组件 | 技术 | 说明 |
|------|------|------|
| 后端服务 | FastAPI + uvicorn | 提供 REST API 和 WebSocket 服务 |
| 前端服务 | Vue 3 + Vite | 提供 Web 用户界面 |
| 数据库 | SQLite 3.x | 存储任务、攻击用例、检测结果、审计事件、评估报告 |
| LLM 服务 | Ollama | 本地运行红队、蓝队、目标模型 |
| 外部 API | DeepSeek | 评估报告 AI 生成 |

### 1.2 关键路径

| 路径 | 说明 |
|------|------|
| backend/main.py | 应用入口 |
| backend/config/settings.py | 运行时配置 |
| backend/config/blue_policies.yaml | 蓝队检测策略 |
| backend/config/target_agents.yaml | 目标智能体配置 |
| red_blue_platform.db | SQLite 数据库文件 |

## 2. 日常维护

### 2.1 服务状态检查

**检查后端服务**：

```bash
curl http://localhost:8000/docs
```

正常返回 Swagger API 文档页面。

**检查 Ollama 服务**：

```bash
ollama list
```

正常返回已安装的模型列表。

**检查数据库**：

```bash
sqlite3 red_blue_platform.db ".tables"
```

正常返回 5 张表名。

### 2.2 服务启停

**启动后端**：

```bash
cd backend
source venv/bin/activate  # Linux/Mac
# 或 venv\Scripts\activate  # Windows
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

**启动前端**：

```bash
cd frontend
npm run dev
```

**停止服务**：在终端中按 Ctrl+C 停止。

### 2.3 日志查看

后端日志输出到控制台，包含以下类型：
- 结构化日志（observability/logging.py）
- 审计日志（observability/audit_log.py）
- 链路追踪（observability/tracing.py）

关键日志级别：INFO（正常操作）、WARNING（异常但可恢复）、ERROR（需要处理）。

### 2.4 数据库备份

SQLite 数据库为单文件，备份只需复制文件：

```bash
cp red_blue_platform.db red_blue_platform_backup_$(date +%Y%m%d).db
```

建议每周备份一次，或在重要操作前备份。

### 2.5 数据库清理

删除历史任务数据（级联删除所有关联数据）：

```bash
sqlite3 red_blue_platform.db "DELETE FROM tasks WHERE created_at < datetime('now', '-30 days');"
```

建议定期清理超过 30 天的历史数据，避免数据库文件过大。

## 3. 配置管理

### 3.1 环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| DATABASE_URL | sqlite:///./red_blue_platform.db | 数据库连接 |
| OLLAMA_BASE_URL | http://localhost:11434 | Ollama 服务地址 |
| RED_MODEL | dolphin-mistral:latest | 红队模型 |
| TARGET_MODEL | qwen3:1.7b | 目标模型 |
| BLUE_MODEL | gemma2:2b | 蓝队模型 |
| EVAL_MODEL | deepseek-v4-flash | 评估模型 |
| EXTERNAL_EVAL_API_KEY | - | DeepSeek API 密钥 |
| DEFAULT_MAX_ROUNDS | 2 | 默认最大轮次 |
| LLM_TIMEOUT | 120 | LLM 调用超时（秒） |

### 3.2 蓝队策略配置

修改 `backend/config/blue_policies.yaml` 可调整检测策略：

- 关键词库：添加/删除/修改关键词
- 敏感字段：调整敏感字段列表
- 角色权限：修改角色权限映射
- 检测规则：调整规则的匹配条件和动作

修改后重启后端服务生效。

### 3.3 目标智能体配置

修改 `backend/config/target_agents.yaml` 可调整目标智能体：

- 工具列表：添加/删除可用工具
- 智能体描述：调整智能体的行为描述
- 新增智能体：添加新的智能体类型

修改后重启后端服务生效。

## 4. 故障排查

### 4.1 任务启动失败（503 错误）

**现象**：启动任务时返回 503，错误信息 "Ollama service is not available"。

**排查步骤**：
1. 检查 Ollama 是否运行：`ollama list`
2. 检查 Ollama 端口：`curl http://localhost:11434`
3. 检查模型是否已拉取：确认所需模型在 ollama list 中

**解决方案**：
1. 启动 Ollama 服务
2. 拉取缺失的模型：`ollama pull <model_name>`

### 4.2 任务长时间停留在 RUNNING

**现象**：任务启动后长时间不完成。

**排查步骤**：
1. 检查控制台日志，确认是否有错误输出
2. 检查 LLM 模型是否正常响应
3. 检查攻击用例数量是否过多

**说明**：
- 每次 LLM 调用超时 120 秒
- 攻击用例较多时，总执行时间会增加
- 若超过合理时间（如 10 分钟），建议检查 Ollama 日志

### 4.3 WebSocket 连接不稳定

**现象**：前端数据更新中断或频繁断开。

**排查步骤**：
1. 检查后端服务是否正常运行
2. 检查网络连接是否稳定
3. 检查浏览器控制台是否有错误

**说明**：
- 前端已实现自动重连（1.5 秒间隔）
- 重连后数据会自动同步
- 如频繁断开，建议检查网络环境和后端负载

### 4.4 评估报告未生成

**现象**：任务完成后报告中 summary 和 recommendations 为空。

**排查步骤**：
1. 检查 DeepSeek API 密钥是否配置
2. 检查网络是否能访问 api.deepseek.com
3. 检查 API 密钥是否有效

**说明**：
- DeepSeek API 不可用时，系统会使用规则引擎兜底
- 兜底模式下报告仍会生成，但缺少 AI 生成的摘要和建议

### 4.5 数据库文件损坏

**现象**：启动时报数据库错误。

**解决方案**：
1. 停止服务
2. 从备份恢复数据库文件
3. 若无备份，删除数据库文件，重启服务自动重建（历史数据丢失）

### 4.6 新增模型不生效

**现象**：修改了环境变量中的模型名称，但任务仍使用旧模型。

**排查步骤**：
1. 确认环境变量已正确设置
2. 确认模型已通过 ollama pull 拉取
3. 重启后端服务

## 5. 性能优化

### 5.1 Ollama 性能调优

- 内存不足时可使用更小的模型（如 qwen2:0.5b 替代 qwen3:1.7b）
- 设置 OLLAMA_NUM_PARALLEL 环境变量控制并发请求数
- 设置 OLLAMA_MAX_LOADED_MODELS 控制同时加载的模型数

### 5.2 数据库性能

- 定期清理历史数据，保持数据库文件大小合理
- 若数据库文件过大（> 100 MB），考虑迁移到 PostgreSQL

### 5.3 前端性能

- 审计事件过多时，限制时间线展示数量
- ECharts 图表数据量大时，启用数据采样

## 6. 升级指南

### 6.1 代码升级

1. 停止服务
2. 备份数据库文件
3. 拉取最新代码
4. 安装新依赖
5. 执行数据库迁移（如有）
6. 重启服务

### 6.2 模型升级

1. 拉取新模型：`ollama pull <new_model>`
2. 修改环境变量中的模型名称
3. 重启服务

### 6.3 回滚

1. 停止服务
2. 恢复备份的数据库文件
3. 恢复上一版本代码
4. 重启服务

## 3. 各阶段详细进度

### 3.1 需求分析与架构设计（第 1-2 天）

**计划内容**：
- 需求文档编写
- 系统架构设计
- 接口契约制定
- 技术选型确认

**实际完成情况**：

完成了平台整体需求分析，确定了四个核心角色（红队、蓝队、目标智能体、评估系统）和四阶段对抗流程（攻击链规划 → 防御分发 → 评估流 → 报告生成）。设计了 9 大模块的分层架构，确定了模块间的接口契约和数据依赖关系。技术选型确认为 FastAPI + LangGraph + SQLAlchemy + Vue 3 + Pinia + Element Plus + ECharts。

**关键产出**：
- 需求规格说明书
- 系统架构设计图（9 模块分层）
- 双总线事件驱动架构设计
- LangGraph 三节点状态图编排方案
- 接口契约草案

### 3.2 后端核心开发（第 3-7 天）

**计划内容**：
- 编排层：LangGraph 状态图实现
- 红队模块：攻击生成与变异进化
- 蓝队模块：三道防线检测
- 目标系统：智能体模拟与沙箱执行
- 评估模块：报告生成与指标计算
- 事件总线：双总线架构实现
- 持久化层：5 张数据库表与 CRUD 操作
- LLM 模块：统一客户端封装

**实际完成情况**：

**第 3-4 天**：完成基础设施层开发。事件总线（FastPathBus + SlowPathBus）实现，支持 13 种 Fast Path 事件和 8 种 Slow Path 事件。持久化层完成 5 张数据库表模型定义和 CRUD 操作。LLM 统一客户端封装完成，支持 Ollama 本地调用和 DeepSeek 外部 API 调用。

**第 5-6 天**：完成业务层开发。编排层实现 LangGraph 三节点状态图（plan_attack_chain → dispatch_defense_pipeline → evaluate_stream）。红队模块实现攻击链规划、RedBench 数据集加载、LLM 攻击生成和 5 种变异策略。蓝队模块实现输入检测、工具审计、输出检测三道防线，采用规则引擎和 LLM 模型双通道并发检测。目标系统实现金融智能体和客服智能体两种场景，以及 9 个工具函数的沙箱执行。

**第 7 天**：完成评估模块和 API 层。评估模块实现 6 项核心指标计算、RedBench 基准对比和 AI 评估报告生成。API 层实现 7 个 REST API 端点和 1 个 WebSocket 端点，支持请求参数校验、错误处理和 Ollama 健康检查。

**关键产出**：
- 9 个后端模块完整代码
- 5 张数据库表
- 7 个 REST API 端点
- 1 个 WebSocket 端点
- 3 个 YAML 配置文件

### 3.3 前端开发与集成（第 8-11 天）

**计划内容**：
- 6 个核心组件开发
- Pinia 状态管理
- WebSocket 实时推送
- 前后端联调

**实际完成情况**：

**第 8-9 天**：完成前端基础框架搭建。Vue 3 项目初始化，配置路由（两个路由：首页和任务详情）、Pinia 状态管理、Axios HTTP 封装和 WebSocket 连接管理。完成左侧边栏组件（任务创建弹窗、任务列表切换）和任务状态头部组件。

**第 10-11 天**：完成核心可视化组件。实现对抗态势流程图（六阶段可视化流程）、数据对比面板（三方输出对比、变异任务卡片轮播）、安全洞察图表（ECharts 图表与核心指标卡片）和审计事件时间线（Fast Path 和 Slow Path 事件分类展示）。完成前后端 WebSocket 实时推送联调，实现版本比对机制和断线自动重连。

**关键产出**：
- 6 个前端组件
- Pinia 状态管理仓库
- WebSocket 实时推送（每 0.5 秒）
- 断线自动重连机制

### 3.4 联调测试与优化（第 12-13 天）

**计划内容**：
- 系统联调
- 性能优化
- Bug 修复

**实际完成情况**：

**系统联调**：完成前后端全流程联调，验证了从任务创建到评估报告生成的完整链路。确认了两种目标智能体类型（金融、客服）和多种 RedBench 数据集的正常工作。

**关键问题解决**：
- 红队自动进化失败：LLM 变异生成的 Payload 格式不稳定，实现了多层容错解析（JSON 解析 → 字典字段提取 → Markdown 剥离）
- 模型无法生成恶意攻击提示词：开源模型内置安全限制，通过系统提示词重定位为安全评估用途解决，同时 RedBench 数据集兜底
- 任务进度实时化展示：实现了 WebSocket 版本比对机制，仅在数据变化时推送，平衡了实时性和传输效率

**性能优化**：
- 蓝队双通道并发检测：规则引擎和 LLM 模型并行执行，规则先行命中高风险时取消 LLM 调用
- 红队异步变异：使用线程池异步执行，不阻塞主攻防流程

### 3.5 文档编写与交付（第 14 天）

**实际完成情况**：

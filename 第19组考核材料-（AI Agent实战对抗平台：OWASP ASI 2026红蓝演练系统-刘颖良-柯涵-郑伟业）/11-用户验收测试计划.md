# 红蓝对抗平台 — 用户验收测试计划

---

## 1. 引言

### 1.1 目的

本用户验收测试计划旨在定义红蓝对抗平台的验收标准和测试流程，确保平台满足用户需求并达到可交付的质量标准。

### 1.2 验收范围

| 验收项 | 说明 |
|--------|------|
| 任务创建与启动 | 用户能够创建并启动红蓝对抗任务 |
| 红队攻击功能 | 系统能够自动生成攻击提示词并执行攻击 |
| 蓝队防御功能 | 系统能够进行输入检测、工具审计和输出检测 |
| 目标智能体模拟 | 系统能够正确模拟金融智能体和客服智能体 |
| 自动进化功能 | 红队能够根据检测结果自动变异 Payload |
| 评估报告功能 | 系统能够自动生成评估报告 |
| 实时可视化 | 前端能够实时展示对抗流程 |
| 审计事件 | 系统能够记录完整的审计事件 |

### 1.3 验收标准

- 核心功能必须全部通过验收测试
- 非核心功能的缺陷不超过 3 个
- 不存在严重级别（阻断性）缺陷
- 用户操作流程完整可用

---

## 2. 验收测试场景

### 场景 1：金融智能体安全评估

**业务描述**：安全测试人员对金融智能体进行安全评估，检测其是否能够抵抗越权转账攻击。

**参与角色**：安全测试人员

**前置条件**：
- 系统已部署并正常运行
- Ollama 服务可用
- 所需模型已加载

**验收步骤**：

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开系统 Web 界面 | 显示工作区页面 |
| 2 | 点击「新建任务」 | 弹出任务创建对话框 |
| 3 | 选择目标智能体为 financial_agent | 选中状态正确 |
| 4 | 勾选 RedBench 数据集，至少勾选一个涉及越权转账的数据集 | 数据集列表正常展示 |
| 5 | 设置最大轮次为 2 | 数值设置正确 |
| 6 | 点击「创建」 | 任务创建成功，出现在左侧任务列表中 |
| 7 | 点击任务卡片的「开始」按钮 | 任务状态变为 RUNNING |
| 8 | 观察态势流程图 | 六阶段流程逐步展示，状态颜色正确 |
| 9 | 观察数据对比面板 | 红队提示词、目标响应、蓝队检测结果正确展示 |
| 10 | 等待任务完成 | 任务状态变为 COMPLETED |
| 11 | 查看安全洞察图表 | 核心指标卡片和图表正确显示 |
| 12 | 查看评估报告 | 报告包含攻击成功率、检测率、阻断率等指标 |
| 13 | 查看修复建议 | 报告包含 AI 生成的修复建议 |
| 14 | 查看审计事件时间线 | 审计事件按时间顺序正确展示 |

**验收标准**：
- 所有 14 个步骤全部通过
- 攻击成功率 < 100%（表示蓝队至少检测到部分攻击）
- 检测率 > 0%（表示蓝队检测功能正常）
- 评估报告包含正确的指标数值

### 场景 3：变异进化功能验证

**业务描述**：验证红队能够在攻击被蓝队阻断后自动变异 Payload 并重新攻击。

**参与角色**：安全测试人员

**前置条件**：同场景 1

**验收步骤**：

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 创建任务，选择包含高风险攻击的数据集，max_rounds 设为 2 或 3 | 任务创建成功 |
| 2 | 启动任务 | 任务开始执行 |
| 3 | 观察是否出现变异任务卡片 | 攻击被阻断后出现变异任务 |
| 4 | 查看变异任务详情 | 变异任务包含原始 Payload 和变异后 Payload |
| 5 | 观察变异后的用例是否重新执行 | 变异用例出现在新的攻击回合中 |
| 6 | 检查变异策略 | 策略选择符合失败阶段 |
| 7 | 检查轮次限制 | 所有用例 round_no 不超过 max_rounds |

**验收标准**：
- 至少出现 1 个变异任务
- 变异任务包含正确的父用例 ID
- 变异策略选择合理
- 轮次不超过限制

### 场景 6：WebSocket 实时推送

**业务描述**：验证 WebSocket 实时推送功能的稳定性和数据准确性。

**参与角色**：安全测试人员

**前置条件**：同场景 1

**验收步骤**：

| 步骤 | 操作 | 预期结果 |

| 2 | 观察前端数据是否实时更新 | 态势流程图、数据面板、审计事件实时更新 |
| 3 | 观察更新频率 | 约 0.5 秒一次 |
| 4 | 任务完成后确认连接自动关闭 | 任务完成后连接关闭 |
| 5 | 模拟网络断开后恢复 | 前端自动重连 |

**验收标准**：
- 数据实时更新，无明显延迟
- 连接稳定，无明显断开
- 任务完成后自动关闭

## 3. 验收结论标准

| 结论 | 条件 |
|------|------|
| 通过 | 所有 6 个场景的验收标准全部满足，无严重缺陷 |
| 有条件通过 | 核心场景（场景 1、2）通过，非核心场景存在不超过 2 个未通过项，无严重缺陷 |
| 不通过 | 核心场景未通过，或存在严重缺陷 |

# 红蓝对抗平台 — 部署计划

---

## 1. 部署概述

### 1.1 部署目标

将红蓝对抗平台部署到目标服务器，确保系统能够稳定运行，用户可以通过浏览器访问并使用平台的全部功能。

### 1.2 部署架构

```
[用户浏览器] <--HTTP/WS--> [FastAPI 服务] <--SQL--> [SQLite 数据库]
                                |
                                +--HTTP--> [Ollama 服务 (localhost:11434)]
                                |
                                +--HTTPS--> [DeepSeek API (api.deepseek.com)]
```

### 1.3 部署环境要求

| 类别 | 最低要求 | 推荐配置 |
|------|---------|---------|
| 操作系统 | Windows 10/11 或 Linux | Windows 11 / Ubuntu 22.04 |
| 内存 | 16 GB | 32 GB（运行多个 LLM 模型） |
| 磁盘 | 20 GB 可用空间 | 50 GB SSD（存储模型文件） |
| 网络 | 可访问外网（DeepSeek API） | 稳定网络连接 |
| Python | 3.10+ | 3.10 或 3.11 |
| Node.js | 18+ | 18 LTS |

## 2. 部署前准备

### 2.1 软件安装

| 软件 | 安装方式 | 验证命令 |
|------|---------|---------|
| Python 3.10+ | 官网下载安装 | python --version |
| pip | 随 Python 安装 | pip --version |
| Node.js 18+ | 官网下载安装 | node --version |
| npm | 随 Node.js 安装 | npm --version |
| Ollama | 官网下载安装 | ollama --version |
| Git | 官网下载安装 | git --version |

### 2.2 模型准备

通过 Ollama 拉取所需模型：

| 模型 | 用途 | 拉取命令 | 预估大小 |
|------|------|---------|---------|
| dolphin-mistral:latest | 红队攻击生成 | ollama pull dolphin-mistral:latest | ~4 GB |
| gemma2:2b | 蓝队安全检测 | ollama pull gemma2:2b | ~1.5 GB |
| qwen3:1.7b | 目标智能体模拟 | ollama pull qwen3:1.7b | ~1.5 GB |

**总计约 7 GB 模型存储空间。**

### 2.3 环境变量配置

| 变量名 | 必填 | 说明 |
|--------|------|------|
| EXTERNAL_EVAL_API_KEY | 是 | DeepSeek API 密钥 |
| EVAL_MODEL | 否 | 评估模型，默认 deepseek-v4-flash |
| OLLAMA_BASE_URL | 否 | Ollama 服务地址，默认 http://localhost:11434 |

## 3. 部署步骤

### 3.1 后端部署

**步骤 1：获取代码**

```bash
git clone <repository_url>
cd 红蓝对抗平台/backend
```

**步骤 2：创建虚拟环境**

```bash
python -m venv venv
```

Linux/Mac：
```bash
source venv/bin/activate
```

Windows：
```powershell
venv\Scripts\activate
```

**步骤 3：安装依赖**

```bash
pip install -r requirements.txt
```

**步骤 4：配置环境变量**

```bash
export EXTERNAL_EVAL_API_KEY="your_deepseek_api_key"
```

Windows：
```powershell
$env:EXTERNAL_EVAL_API_KEY="your_deepseek_api_key"
```

**步骤 5：启动服务**

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

**步骤 6：验证后端**

访问 http://localhost:8000/docs 查看 API 文档，确认服务正常运行。

### 3.2 前端部署

**步骤 1：进入前端目录**

```bash
cd ../frontend
```

**步骤 2：安装依赖**

```bash
npm install
```

**步骤 3：构建生产版本**

```bash
npm run build
```

**步骤 4：部署静态文件**

将 `dist/` 目录下的文件部署到 Web 服务器（如 Nginx），或使用 Vite 预览：

```bash
npm run preview
```

### 3.3 整体验证

1. 确保 Ollama 服务运行中：`ollama list`
2. 确保后端服务运行中：访问 http://localhost:8000/docs
3. 确保前端可访问：打开浏览器访问前端地址
4. 创建并启动一个测试任务，验证完整流程

## 4. 部署方式

### 4.1 开发环境部署（推荐用于测试）

- 后端：`uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000`
- 前端：`npm run dev`
- 数据库：SQLite 本地文件，自动创建

### 4.2 生产环境部署

**后端**：
- 使用 gunicorn + uvicorn workers 部署（Linux）
- 使用 IIS + FastCGI 或 Windows Service 部署（Windows）

**前端**：
- 使用 Nginx 反向代理 + 静态文件服务
- Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://localhost:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 5. 部署后检查

| 检查项 | 方法 | 预期结果 |
|--------|------|---------|
| 后端服务启动 | 访问 /docs | 显示 Swagger API 文档 |
| 数据库创建 | 检查 red_blue_platform.db 文件 | 文件存在 |
| Ollama 连接 | 创建并启动任务 | 不返回 503 错误 |
| RedBench 数据集 | 访问 /api/tasks/redbench/datasets | 返回数据集列表 |
| 任务创建 | POST /api/tasks | 返回 201，包含 task_id |
| 任务启动 | POST /api/tasks/{id}/start | 返回 200，状态 RUNNING |
| WebSocket 连接 | 前端建立 WebSocket 连接 | 每 0.5 秒接收数据 |
| 前端访问 | 浏览器打开前端地址 | 页面正常显示 |
| 完整流程 | 创建-启动-查看报告 | 全流程正常 |

## 6. 回滚计划

如果部署后出现严重问题，按以下步骤回滚：

1. 停止后端服务
2. 恢复备份的数据库文件
3. 恢复上一版本的代码
4. 重新启动服务
5. 验证功能正常

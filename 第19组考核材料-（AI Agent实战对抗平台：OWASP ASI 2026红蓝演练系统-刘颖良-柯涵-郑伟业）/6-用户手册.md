# 红蓝对抗平台 — 用户手册

---

## 1. 系统概述

红蓝对抗平台是一个面向 AI Agent 安全评估的自动化对抗演练工具。平台通过红队模拟攻击、蓝队部署防御、目标智能体执行和评估报告生成四位一体的闭环流程，帮助用户评估 AI Agent 的安全性。

### 1.1 核心功能

- **任务管理**：创建、启动、查看红蓝对抗任务
- **红队攻击**：自动生成攻击提示词，模拟真实攻击行为
- **蓝队防御**：输入检测、工具审计、输出检测三道防线
- **目标仿真**：模拟金融智能体和客服智能体两种 AI Agent
- **自动进化**：红队根据检测结果自动变异攻击 Payload
- **评估报告**：自动计算核心指标，生成评估报告和修复建议
- **实时可视化**：WebSocket 实时推送对抗流程

### 1.2 系统要求

- 现代浏览器（Chrome、Firefox、Edge 最新版）
- 网络连接到后端服务

## 2. 快速开始

### 2.1 访问系统

在浏览器中打开系统地址，进入工作区页面。页面左侧为任务管理区域，右侧为任务详情展示区域。

### 2.2 创建第一个任务

1. 点击左侧边栏的「新建任务」按钮
2. 在弹出的对话框中配置任务参数：
   - **目标智能体**：选择 financial_agent（金融智能体）或 customer_agent（客服智能体）
   - **RedBench 数据集**：勾选用于攻击的数据集，至少选择一个。数据集覆盖 7 类 AI 安全风险类型
   - **最大轮次**：设置对抗最大轮次，默认值为 2。轮次越多，红队进化次数越多
   - **攻击技能**：可选，选择特定的攻击技能模板
   - **模型配置**：可选，指定目标模型名称
3. 点击「创建」按钮
4. 任务创建成功后，点击「开始」按钮启动任务

### 2.3 查看任务进度

任务启动后，系统会通过 WebSocket 实时推送任务进度。主要展示区域包括：

- **任务头部**：显示任务状态（PENDING → RUNNING → COMPLETED/FAILED）和创建时间
- **对抗态势流程图**：以六阶段流程可视化展示每轮对抗过程
- **数据对比面板**：展示红队攻击提示词、目标智能体响应和蓝队检测结果的对比
- **安全洞察图表**：通过 ECharts 图表展示核心指标数据
- **审计事件时间线**：按时间顺序展示所有审计事件

## 3. 功能详解

### 3.1 任务管理

#### 3.1.1 创建任务

**操作步骤**：
1. 点击左侧边栏「新建任务」
2. 选择目标智能体类型
3. 勾选 RedBench 数据集（至少一个）
4. 设置最大轮次
5. 点击「创建」

**参数说明**：

| 参数 | 说明 | 必填 |
|------|------|------|
| 目标智能体 | 金融智能体提供余额查询、转账、风控审核等功能；客服智能体提供订单查询、用户信息查询、工单修改等功能 | 是 |
| RedBench 数据集 | 系统从 20 余个子数据集中加载攻击样本，覆盖 ASI01 至 ASI07 七类风险 | 是 |
| 最大轮次 | 设为 1 仅执行一轮攻击；设为 2 或以上，蓝队检测到攻击后红队会进行变异进化 | 是 |
| 攻击技能 | 可选的攻击技能模板，为空时自动匹配 | 否 |
| 模型配置 | 可指定目标模型名称，不指定则使用默认值 | 否 |

#### 3.1.2 启动任务

任务创建后状态为 PENDING，点击「开始」按钮启动。系统会先检查 Ollama 服务可用性，检查通过后任务状态变为 RUNNING。

#### 3.1.3 任务列表

左侧边栏显示所有已创建的任务，按创建时间倒序排列。每个任务卡片显示任务 ID、状态、目标智能体和创建时间。点击任务卡片可查看任务详情。

#### 3.1.4 任务详情

任务详情页面包含以下信息：
- 任务基本信息（ID、状态、目标智能体、风险类型、攻击技能、轮次、模型等）
- 攻击用例列表（每条用例包含攻击提示词、风险类型、严重程度、变异策略等）
- 检测结果列表（每条结果包含检测阶段、动作、风险等级、置信度等）
- 评估报告（任务完成后自动生成）

### 3.2 对抗态势流程图

态势流程图以可视化方式展示六阶段对抗过程：

| 阶段 | 图标 | 说明 |
|------|------|------|
| 攻击请求 | 红队图标 | 红队发起攻击，发送攻击提示词 |
| 输入检测 | 蓝队图标 | 蓝队对攻击提示词进行输入检测 |
| 目标决策 | 目标图标 | 目标智能体分析提示词并做出决策 |
| 工具审计 | 蓝队图标 | 蓝队对目标智能体的工具调用进行审计 |
| 沙箱执行 | 工具图标 | 在沙箱环境中执行目标智能体的工具调用 |
| 输出检测 | 蓝队图标 | 蓝队对目标智能体的执行结果进行输出检测 |

各阶段状态通过颜色区分：
- 绿色：通过（allow）
- 红色：阻断（block）
- 橙色：降级（degrade）
- 灰色：未执行或跳过

### 3.3 数据对比面板

数据对比面板展示三方输出内容：

- **红队提示词**：红队生成的攻击提示词原文
- **目标响应**：目标智能体对攻击提示词的响应文本和工具调用计划
- **蓝队检测结果**：蓝队三道防线的检测结果，包括动作、风险等级、检测原因

变异任务通过卡片轮播形式展示，点击可查看变异前后的 Payload 对比。

### 3.4 安全洞察图表

安全洞察区域包含：

- **核心指标卡片**：攻击成功率、检测率、阻断率、误报率、漏报率、风险覆盖率
- **ECharts 图表**：以图表形式展示指标分布和趋势
- **AI 评估总结**：通过评估模型生成的综合评估报告，包含修复建议

### 3.5 审计事件时间线

审计事件时间线按时间顺序展示所有事件，分为两类：

- **Fast Path 事件**：同步执行路径中的事件，如攻击请求、检测结果、回合结果等
- **Slow Path 事件**：异步可观测路径中的事件，如审计日志、模型追踪、指标记录等

每个事件显示事件类型、执行代理、工具名称、风险等级和消息内容。事件通过颜色编码区分类型，通过标签标识涉及的代理和工具。

## 4. 评估报告解读

### 4.1 核心指标

| 指标 | 含义 | 理想值 |
|------|------|--------|
| 攻击成功率 | 成功绕过防御的攻击比例 | 越低越好 |
| 检测率 | 被检测到的攻击比例 | 越高越好 |
| 阻断率 | 被直接阻断的攻击比例 | 越高越好 |
| 误报率 | 正常操作被误判为攻击的比例 | 越低越好 |
| 漏报率 | 攻击未被检测到的比例 | 越低越好 |
| 风险覆盖率 | 已覆盖的风险类型占请求类型的比例 | 越高越好 |

### 4.2 RedBench 基线对比

评估报告将平台检测结果与 RedBench 基准数据按风险类型逐一对比，帮助用户了解当前防御能力在行业中的水平。标注低于基线的风险类型，提示需要加强的防御方向。

### 4.3 修复建议

评估报告中的修复建议由 AI 评估模型生成，从红方视角、目标系统视角和蓝方模型视角三个维度分析，提供具体的防御改进方向。

## 5. 常见问题

### 5.1 任务启动失败

**现象**：点击「开始」后，任务状态变为 FAILED，错误信息显示 "Ollama service is not available"。

**原因**：后端检测到 Ollama 服务不可用。

**解决**：确保后端服务器上的 Ollama 服务已启动，且所需模型已拉取。

### 5.2 任务状态长时间停留在 RUNNING

**现象**：任务启动后，长时间处于 RUNNING 状态。

**原因**：LLM 模型推理耗时较长，特别是当攻击数量较多或轮次较大时。

**说明**：每次 LLM 调用超时时间为 120 秒，攻击用例较多时任务执行时间会相应增加。请耐心等待。

### 5.3 WebSocket 连接断开

**现象**：前端显示连接断开，数据不更新。

**原因**：网络波动或后端服务重启。

**解决**：系统会自动重连（1.5 秒间隔），无需手动操作。重连后数据会自动同步。

### 5.4 评估报告未生成

**现象**：任务完成后，评估报告区域显示 "Task report has not been generated"。

**原因**：任务执行过程中出现异常，评估报告未能生成。

**说明**：检查任务状态是否为 COMPLETED，若为 FAILED 则说明任务执行异常，请查看错误信息。

## 6. 操作注意事项

1. 创建任务时至少选择一个 RedBench 数据集，否则无法创建。
2. 任务启动后不可撤销，请确认参数配置正确后再启动。
3. 最大轮次建议设为 2，轮次过多会增加执行时间，且变异效果可能递减。
4. 评估报告在任务完成后自动生成，无需手动操作。
5. 审计事件在任务执行过程中实时生成，可在任务完成后查看完整事件列表。
6. 切换任务时，WebSocket 连接会自动切换到新任务，旧任务的连接自动关闭。
